# 隐私与 AI 使用说明

> 面向未成年人产品的合规说明。评委问数据问题时，给这一份。
> 对应线上页面：https://awkn.cn/game/privacy.html

---

## 一、结论先行

| 问题 | 回答 |
|---|---|
| 要注册吗？ | **不要**。学生和教师全程免注册、无账号。 |
| 采集姓名/手机/学校吗？ | **不采集**，产品里没有任何输入这些信息的地方。 |
| 采集是默认开的吗？ | **默认关闭**。不明示同意，一条数据都不上传。 |
| 学习进度存哪？ | **只存学生自己的浏览器**，服务端从不接收。 |
| AI 会看到学生个人信息吗？ | **不会**。发给 AI 的只有剧本 ID 和聚合后的答题统计。 |
| 数据能删吗？ | 能。清浏览器数据即清空本地进度；服务端匿名记录可按匿名 ID 删除。 |

## 二、采集了什么（完整清单）

### 2.1 默认关闭

前端 `assets/js/identity-client.js`：

```js
// 面向乡村学校与未成年人：匿名行为采集默认关闭，需用户或教师主动开启。
function isTrackingEnabled() {
  return local.getItem(PREFIX + 'data_improvement') === 'true';
}
```

采用**显式同意（opt-in）**语义：只有本地明确存了 `'true'` 才算开启。
未设置、清了浏览器数据、值为其他任何内容，一律视为**关闭**。
未同意时事件在客户端就被丢弃，**不会发出网络请求**。

### 2.2 事件白名单（18 类，全部）

只有 `data/event_catalog.json` 中登记的事件名才被服务端接受，其余返回 `EVENT_NOT_ALLOWED`。

| 分类 | 事件名 |
|---|---|
| 页面 | `page.view` |
| 剧本 | `script.open`、`script.start`、`script.act_enter`、`script.choice`、`script.evidence_open`、`script.knowledge_open`、`script.card`、`script.ending` |
| 测验 | `quiz.answer`、`quiz.complete` |
| 教学 AI | `lesson_plan.request`、`lesson_plan.generated`、`learning_review.request`、`learning_review.generated` |
| 用户表达 | `feedback.submitted`、`wish.submitted`、`wish.voted` |

### 2.3 字段白名单（二次裁剪）

每类事件再按 `allowedPayloadKeys` 裁剪，**未登记的字段直接丢弃**，不入库。

示例：

| 事件 | 允许字段 |
|---|---|
| `script.act_enter` | `scriptId`、`actId`、`actTitle` |
| `script.choice` | `scriptId`、`nodeId`、`choiceIndex`、`choiceText`、`actId`、`timed` |
| `quiz.complete` | `scriptId`、`score`、`total`、`pct`、`learningTier` |

> 这一层是**服务端强制**的，不是前端自觉。即使有人伪造请求塞入额外字段，也进不了数据库。

### 2.4 明确不采集

- 姓名、手机号、身份证、学校、班级、学号
- 密码、键盘输入过程、剪贴板
- 屏幕录像、摄像头、麦克风、地理位置
- 完整 `localStorage`、Cookie 全量、浏览器指纹
- 站外行为、跨站追踪、第三方广告 SDK（**产品内无任何第三方追踪脚本**）

### 2.5 关于 IP

服务端不存明文 IP。仅用于频率限制的哈希值（`ipHash`），不可逆、不与身份关联、不长期保留。

## 三、数据存在哪、留多久

| 数据 | 位置 | 说明 |
|---|---|---|
| 完整学习进度（答题、错题、知识掌握度） | **学生浏览器 localStorage** | 服务端从不接收；清浏览器即清空 |
| 匿名互动事件 | 服务端 SQLite `product_events` | 匿名 ID，无法反查个人 |
| AI 运行记录 | 服务端 `ai_runs` | 输入侧**只存 `{任务类型, 剧本ID}`**，不存学生答题原文；输出侧存 AI 生成的教案/复盘文本，用于质量追溯 |
| 用户主动提交的反馈 / 愿望 | 服务端 `feedback` / `wishes` | 用户主动填写的内容 |
| 管理员账号 | 服务端 `admin_users` | 仅管理员，密码哈希存储 |

匿名 ID 由浏览器本地随机生成，换设备或清数据即换 ID，**无法跨设备关联到同一个人**。

## 四、AI 使用说明

### 4.1 用了什么模型

| 角色 | 供应商 | 模型 |
|---|---|---|
| 主用 | OpenCode | `deepseek-v4-flash` |
| 备用 | MiniMax | `MiniMax-M2.5` |
| 兜底 | 无（本地） | `data/rule_templates.json` 规则模板 |

均通过 **OpenAI 兼容协议**调用，换供应商只需改环境变量，不改代码。

### 4.2 发给 AI 的是什么

**教师导学卡**（`lesson_plan`）：

```json
{ "scriptId": "american_revolution", "duration": 40,
  "studentLevel": "average", "teachingFocus": "...", "usageMode": "projection" }
```

**学生学习复盘**（`learning_review`）：

```json
{ "scriptId": "industrial_revolution",
  "learningData": { "completed": true, "quizCorrect": 6, "quizTotal": 10,
    "quizPct": 60, "essayPct": 70, "tier": "average",
    "wrongAnswers": [ { "question": "...", "userAnswer": "...", "correctAnswer": "..." } ] } }
```

> **均不含任何身份信息**——没有姓名、没有匿名 ID、没有 IP、没有设备信息。
> 学情数据是本机聚合后的统计，且由学生主动点击「生成复盘」时才发送。

### 4.3 AI 输出如何被约束

- 强制 JSON schema，字段类型和数量在服务端二次校验
- 剥离模型思考标签（`<think>`）与 Markdown 代码围栏
- 类型不符时自动 coerce（字符串→数组、补缺失字段）
- 校验不通过 → 视为该供应商失败 → 走下一层降级

### 4.4 AI 失败时会怎样

三层降级，**永远有输出**：

1. 主模型失败（超时 / 限流 / 格式坏）→ 自动切备用模型
2. 备用也失败 → 落本地规则模板，返回 `mode: "rule"`
3. 前端明确展示当前是 AI 生成还是规则模板，**不隐瞒**

每次调用都记录到 `ai_runs`，后台 dashboard 的 `aiRuleFallbackToday` 实时暴露降级次数。

### 4.5 AI 的边界（对老师说清楚）

- AI 输出是**教学建议**，不是标准答案，采纳与否由老师判断
- AI 不批改作业、不给学生打分、不生成学生评价
- AI 不做任何影响学生权益的自动化决策
- 历史学科内容以教材为准，AI 只做编排与归因，不改写史实

## 五、未成年人保护专项

| 措施 | 实现 |
|---|---|
| 无账号体系 | 学生教师全程免注册，从结构上杜绝个人信息收集 |
| 采集默认关闭 | `isTrackingEnabled = false`，需明示同意 |
| 隐私说明可随时查看 | `privacy.html`，首页常驻入口 |
| 无社交功能 | 无聊天、无私信、无 UGC 互相可见（愿望池需管理员审核后才公开） |
| 无诱导消费 | 完全免费，无内购、无广告、无积分商城 |
| 无第三方追踪 | 产品内不含任何第三方分析/广告 SDK |
| 内容合规 | 第三方角色 IP 已从源码物理清理，`scripts/validate-ip.mjs` 作 CI 门禁（436 文件 0 违规） |

## 六、可验证性

以下都可现场核验，不是口头承诺：

```bash
# 1) 事件白名单是明文配置，可直接看
cat data/event_catalog.json

# 2) 采集默认关闭，可直接看源码
grep -n "isTrackingEnabled" assets/js/identity-client.js

# 3) 非白名单事件被拒（返回 EVENT_NOT_ALLOWED）
curl -X POST https://awkn.cn/game/api/v1/events/batch \
  -H "Content-Type: application/json" \
  -d '{"events":[{"name":"evil.steal","payload":{"x":1}}]}'

# 4) 白名单外字段被裁剪（payload 里塞的额外字段不会入库）
# 5) IP 门禁检查
npm run check   # 含 validate-ip.mjs，扫描全部源码
```
