# 一、结论先行

现有工程是一套以静态 HTML、共享 `engine.js`、`data-store.js` 和 `localStorage` 为核心的互动学习产品。五个剧本、知识测试、卡牌和知识星系均保留。

本次工程升级采用“静态前端 + 轻量 API 服务 + SQLite + 管理员后台”的旁路结构：

```text
现有静态页面与五个剧本
        │
        ├─ 本机学习数据：localStorage
        │
        ├─ 产品事件：EventClient
        │          ↓
        ├─ AI 导学/复盘：ApiClient
        │          ↓
        └─ 反馈/许愿池：ApiClient
                   ↓
             Node.js API 服务
                   ↓
        SQLite / AI Provider / Admin API
                   ↓
             管理员后台
```

核心原则：

- 原剧情可以脱离后端继续运行；
- 新服务故障时，剧情、测试和本机进度不受影响；
- AI 故障自动转规则版；
- 事件上传失败进入本机队列；
- 管理员只能看到事件目录允许的数据；
- 不采集密码、屏幕录像、键盘输入和站外行为。

| 学习数据 | `data-store.js` + `localStorage` | 升级版本、聚合 API、兼容迁移 |
| 学习页面 | `my-learning.html` | 增加复盘入口与反馈入口 |
| 剧本详情 | `script-detail.html` | 增加导学卡入口 |

| 知识星系 | Three.js + D3 | 保持，失败时降级为列表 |

| 后端 | 未发现正式 API 服务 | 新增 `server/` |
| 管理后台 | 无 | 新增 `admin/` |

## 2.2 当前限制

1. 页面引用的 `dist/output.css` 无稳定构建来源；
2. 账号、密码和学习进度全部在浏览器本机；
3. 没有服务端事件采集，管理员无法跨设备查看互动；
4. 没有 AI 代理接口，前端不能安全保存模型密钥；
5. 剧本和知识点元数据重复，存在数量和结局口径漂移；
6. 现有引擎没有统一业务事件钩子；
7. 没有反馈、许愿池、审核和路线图数据结构；
8. 没有管理员正式登录、权限和操作审计。

# 三、目标技术架构

## 3.1 技术选型

| 层 | 选型 | 原因 |
|---|---|---|
| 用户前端 | 原生 HTML/CSS/JavaScript | 复用现有工程，避免整体迁移 |
| 管理后台 | 原生 HTML/CSS/JavaScript | 与现有技术栈一致，比赛期开发快 |
| API 服务 | Node.js + Fastify | 轻量、结构化校验、日志和测试方便 |
| 数据校验 | Zod | 请求、AI 输出和配置共用 Schema |
| 数据库 | SQLite，WAL 模式 | 单机部署简单，满足 MVP 规模 |
| 数据访问 | Repository 层 | 为后续切换关系数据库留接口 |
| 管理员密码 | Argon2id 哈希 | 服务端正式账号，不保存明文 |
| 管理员会话 | 服务端 Session + HttpOnly Cookie | 避免前端持有长期令牌 |
| 日志 | Fastify/Pino 结构化日志 | traceId、错误定位和脱敏 |
| 测试 | `node:test` + API 注入测试 | 减少测试依赖，适合当前仓库 |
| 反向代理 | Nginx | 静态文件和 `/api/` 同域 |
| 进程管理 | systemd | 服务自启、健康检查和日志统一 |

## 3.2 为什么不用前端框架重构

本期目标是把成熟剧本带入真实教学和产品反馈闭环。框架迁移会同时触碰五个剧本、资源路径、音视频、知识星系和本机进度，风险远高于收益。

管理员后台页面数量有限，原生实现足以支撑：

- 登录；
- 总览；
- 事件查询；
- 匿名用户时间线；
- 反馈处理；
- 愿望审核；
- 路线图；
- 审计日志。

## 3.3 为什么保留 localStorage

学生学习过程中可能遇到网络不稳定。剧情状态、错题和进度保存在本机，可以保证：

- 无网络继续学习；
- API 故障不丢进度；
- 用户无需注册；
- 不把完整学习档案默认上传云端。

服务端只接收经过事件白名单约束的交互事实和用户主动提交内容。

# 五、运行时链路

## 5.1 学生剧情链路

```text
页面加载
→ IdentityClient 读取/生成 anonymousId
→ EventClient 创建 sessionId
→ 剧情继续使用 engine.js
→ 关键节点调用 GameHooks.emit
→ EventClient 校验事件并入队
→ 批量 POST /api/v1/events/batch
→ 失败则保存本机待重试队列
```

剧情主流程永远不等待事件接口。

## 5.2 教师导学卡链路

```text
script-detail.html
→ 读取 SCRIPT_REGISTRY 与 teaching_metadata
→ 用户填写课堂条件
→ 本地参数校验
→ POST /api/v1/teaching-assistant
→ 服务端组装可信上下文
→ 调用 AI Provider
→ 校验结构化输出
→ 成功返回 AI 版
→ 失败返回规则版
→ 前端渲染卡片
```

服务端不信任前端提交的完整历史事实。`scriptId` 对应的正式上下文由服务端配置或签名版本加载。

## 5.3 学生复盘链路

```text
my-learning.html
→ DataStore.getLearningReviewContext(scriptId)
→ 前端删除无关字段
→ POST /api/v1/teaching-assistant
→ AI 或规则版生成
→ 返回掌握、混淆、错因、行动、推荐剧本
```

## 5.4 许愿池链路

```text
用户提交愿望
→ 本地校验与风险提示
→ POST /api/v1/wishes
→ 默认 pending_review
→ 管理员审核
→ public 后进入公开池
→ 匿名用户点亮
→ 管理员更新调研/计划/开发/实现状态
→ 路线图页面展示公开状态
```

## 5.5 管理员链路

```text
管理员登录
→ 服务端校验 Argon2id 密码
→ 建立 HttpOnly Session Cookie
→ 管理接口校验权限
→ 查询事件、反馈、愿望和 AI 运行
→ 所有写操作写入 audit_logs
```

# 八、数据一致性策略

## 8.1 本机进度为学生侧事实来源

完整学习状态继续由 `DataStore` 管理。事件系统不参与恢复剧情进度，避免网络时序影响游戏。

## 8.2 服务端事件为产品分析事实来源

服务端事件采用 append-only，不允许管理员修改历史事件。错误事件通过状态标记或补充事件处理。

## 8.3 许愿池使用事务

以下操作必须在单个数据库事务中完成：

- 合并重复愿望及点亮数；
- 愿望状态更新与历史记录；
- 点亮新增/取消；
- 管理员回复与审计记录。

## 8.4 AI 运行可追踪

每次生成记录：

- task；
- scriptId；
- promptVersion；
- contextVersion；
- provider；
- model；
- mode：`ai` 或 `rule`；
- status；
- latencyMs；
- tokenUsage（供应商提供时）；
- traceId；
- 错误分类。

不记录管理员密钥，不记录无关浏览数据。

# 九、可靠性与降级

| 故障 | 用户表现 | 系统处理 |
|---|---|---|
| API 服务不可用 | 原剧情正常 | 事件入本机队列；AI转本地规则版 |
| AI 超时 | 等待不超过阈值 | 服务端或前端转规则版 |
| AI JSON 不合法 | 不展示破损内容 | 校验失败，重试一次后降级 |
| SQLite 暂时锁定 | 管理数据延迟 | 短重试；事件客户端保留队列 |
| 知识星系失败 | 显示知识列表 | 不白屏 |
| 语音资源失败 | 继续文字剧情 | 记录资源错误事件 |
| 管理员 Session 失效 | 返回登录页 | 不暴露管理数据 |
| 许愿内容违规 | 不公开 | 保持待审核或拒绝 |

# 十、安全设计

1. API 和静态站同域，生产强制 HTTPS；
2. 管理员 Cookie 设置 `HttpOnly`、`Secure`、`SameSite=Strict`；
3. 管理员写接口校验 Origin 和 CSRF Token；
4. 密码使用 Argon2id，数据库只保存哈希；
5. 登录、反馈、愿望和点亮接口均限流；
6. 所有 SQL 使用参数化语句；
7. 用户自由文本服务端限制长度并进行 HTML 转义；
8. 公开愿望只显示审核后的文本；
9. 管理接口按 `viewer`、`editor`、`owner` 三档授权；
10. 数据导出、删除、合并、状态修改写审计日志；
11. AI 密钥只存在服务端环境变量；
12. 日志脱敏 Cookie、Authorization、密码和自由文本正文。

# 十一、性能预算

| 项目 | MVP 目标 |
|---|---|
| 静态剧情首屏 | 不因新增 SDK 增加超过 50 KB gzip |
| 事件 SDK 初始化 | < 50 ms，不阻塞主流程 |
| 单次事件请求 | 批量 1—20 条 |
| 事件接口 P95 | < 300 ms，不含客户端网络 |
| 普通管理查询 P95 | < 500 ms，最多返回 100 条 |
| AI 请求前端超时 | 15 秒后触发规则版 |
| 管理员登录 | P95 < 800 ms |
| 许愿提交 | P95 < 500 ms |
| 数据库文件 | MVP 预警阈值 2 GB |

事件表达到阈值前按月归档，不在比赛版本中建设分布式分析平台。
