# 一、交付目标

本轮工程交付不是一次性重构，而是七次可回退升级：

```text
可复现仓库
→ 公共事件钩子
→ 可运行 API 与数据库
→ AI 导学卡
→ 学生复盘卡
→ 反馈与许愿池
→ 管理员看板与部署
```

任何一天结束，五个原剧本必须保持可运行。

## 8 月 6 日｜M1：公共事件层

### DEV-0101｜匿名身份客户端

新增：`assets/js/identity-client.js`

职责：

- 生成 UUID；
- 保存 `tt_anonymous_id`；
- 创建 `session_id`；
- 记录角色：student/teacher；
- 读取数据改进开关；
- 不读取邮箱、本机密码和真实姓名。

### DEV-0102｜事件客户端

新增：`assets/js/event-client.js`

功能：

- `track(name, payload)`；
- 事件目录白名单；
- 内存队列；
- 5 秒或 20 条批量上传；
- `sendBeacon` 离页发送；
- 失败进入本机队列；
- 最大 200 条，超出丢弃最旧非关键事件；
- 指数退避，最高 5 分钟。

### DEV-0103｜剧情钩子

修改：`engine.js`

新增公共接口：

```js
window.GameHooks = {
  emit(eventName, payload) {},
  register(handler) {}
};
```

接入点：

- 游戏开始；
- 幕次进入；
- 普通选择；
- 限时选择；
- 证据查看；
- 知识点打开；
- 卡牌获取/使用；
- 题目提交；
- 结局解锁；
- 游戏完成。

### DEV-0104｜回归测试

要求：无 EventClient 时 `GameHooks.emit` 为空操作，五个剧本行为与基线一致。

## 8 月 7 日｜M2：API、数据库、管理员认证

### DEV-0201｜Fastify 服务骨架

新增：

- `server/app.js`
- `server/start.js`
- `server/config.js`
- `server/modules/health/`
- `server/middleware/`

接口：

- `GET /api/v1/health/live`
- `GET /api/v1/health/ready`

### DEV-0202｜SQLite 与迁移器

新增首批表：

- schema_migrations
- actors
- sessions
- events
- admin_users
- admin_sessions
- audit_logs
- privacy_preferences

要求：

- WAL；
- foreign_keys=ON；
- busy_timeout；
- 每次迁移事务执行；
- 启动只检查，不自动破坏性迁移。

### DEV-0203｜事件批量接口

`POST /api/v1/events/batch`

约束：

- 最多 20 条；
- 请求不超过 64 KB；
- 事件名必须在目录中；
- payload 按事件类型白名单过滤；
- 客户端 eventId 唯一，重复请求幂等；
- 单条失败不回滚合法事件，返回逐条状态。

### DEV-0204｜管理员认证

接口：

- `POST /api/v1/admin/auth/login`
- `POST /api/v1/admin/auth/logout`
- `GET /api/v1/admin/auth/me`

要求：

- Argon2id；
- HttpOnly Cookie；
- Session 服务端存储；
- 登录限流；
- 登录成功和失败均记录安全日志；
- 默认管理员通过命令行 seed，不写入仓库。

# 六、分支和提交规则

推荐代码分支：

```text
feat/eng-00-build-baseline
feat/eng-01-event-sdk
feat/eng-02-api-db-auth
feat/eng-03-ai-lesson-plan
feat/eng-04-learning-review
feat/eng-05-feedback-wishes
feat/eng-06-admin-console
chore/eng-07-release-hardening
```

提交格式：

```text
feat(events): add batched anonymous event client
feat(ai): add lesson-plan fallback engine
fix(data): migrate per-script play time
chore(release): add systemd service and backup job
```

每个 PR 只覆盖一个 Epic，禁止同时大改剧本正文和基础设施。

# 七、每日门禁

每天合并前必须回答：

1. 五个剧本还能否启动？
2. 无后端时还能否学习？
3. 无 AI 时还能否生成规则卡？
4. 新数据是否有明确用途和白名单？
5. 是否把密钥、密码或用户自由文本写进日志？
6. 数据库迁移是否可重复执行？
7. 本次变更怎样回滚？

任一项无答案，停止合并。

---

# 八、比赛版取舍

时间不足时，按以下顺序砍：

1. 先砍复杂图表；
2. 再砍 CSV 导出；
3. 再砍愿望自动相似合并；
4. 再砍多管理员角色界面；
5. 再砍卡牌细粒度分析；
6. 保留管理员登录、关键事件时间线、导学、复盘、反馈和许愿闭环。

不可砍：

- AI 规则降级；
- 管理员权限；
- 事件白名单；
- 用户文本审核；
- 五剧本回归；
- 构建和回滚。
