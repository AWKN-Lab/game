# ENG-03｜数据库与迁移设计

> 状态：已确认  
> 版本：V1.0  
> MVP 数据库：SQLite  
> 持久化模式：WAL  
> 原则：结构化字段优先，JSON 只承载事件类型差异。

---

# 一、数据库职责

数据库只保存服务端必须共享的数据：

- 匿名身份和产品会话；
- 白名单产品事件；
- AI 运行记录与可选生成结果；
- 用户主动提交的反馈和愿望；
- 愿望点亮、回复和状态历史；
- 管理员账号、会话和审计；
- 隐私偏好。

完整游戏进度继续保存在浏览器 `localStorage`，不自动上传为云档案。

---

# 二、SQLite 启动参数

连接建立后执行：

```sql
PRAGMA foreign_keys = ON;
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;
PRAGMA busy_timeout = 5000;
PRAGMA temp_store = MEMORY;
```

生产数据库文件建议：

```text
/www/wwwroot/awkn-lab/game/shared/data/time-theater.sqlite
```

数据库、WAL、SHM 文件必须位于持久目录，不放进发布版本目录。

# 四、基础表设计

## 4.1 `schema_migrations`

```sql
CREATE TABLE schema_migrations (
  version INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  checksum TEXT NOT NULL,
  applied_at TEXT NOT NULL
);
```

规则：

- 迁移文件命名：`0001_init.sql`；
- 已执行迁移不得修改；
- checksum 不一致时启动失败；
- 每个迁移在事务中执行；
- 破坏性迁移需要独立备份步骤。

## 4.2 `actors`

```sql
CREATE TABLE actors (
  id TEXT PRIMARY KEY,
  anonymous_key TEXT NOT NULL UNIQUE,
  role TEXT NOT NULL CHECK (role IN ('student', 'teacher', 'unknown')),
  first_seen_at TEXT NOT NULL,
  last_seen_at TEXT NOT NULL,
  client_version_first TEXT,
  client_version_last TEXT,
  disabled_at TEXT
);

CREATE INDEX idx_actors_last_seen ON actors(last_seen_at);
```

`anonymous_key` 为客户端随机 ID，不使用设备指纹生成。

## 4.3 `privacy_preferences`

```sql
CREATE TABLE privacy_preferences (
  actor_id TEXT PRIMARY KEY REFERENCES actors(id) ON DELETE CASCADE,
  analytics_enabled INTEGER NOT NULL DEFAULT 1,
  ai_history_enabled INTEGER NOT NULL DEFAULT 0,
  updated_at TEXT NOT NULL,
  source TEXT NOT NULL DEFAULT 'client'
);
```

关闭 analytics 后：

- 不继续接收普通分析事件；
- 仍允许用户主动提交反馈和愿望；
- 必要安全和错误日志按最小化原则处理。

## 4.4 `product_sessions`

```sql
CREATE TABLE product_sessions (
  id TEXT PRIMARY KEY,
  actor_id TEXT NOT NULL REFERENCES actors(id) ON DELETE CASCADE,
  role TEXT NOT NULL,
  started_at TEXT NOT NULL,
  ended_at TEXT,
  entry_page TEXT,
  last_page TEXT,
  script_id TEXT,
  client_version TEXT,
  device_class TEXT,
  locale TEXT,
  event_count INTEGER NOT NULL DEFAULT 0
);

CREATE INDEX idx_sessions_actor_time ON product_sessions(actor_id, started_at DESC);
CREATE INDEX idx_sessions_script_time ON product_sessions(script_id, started_at DESC);
```

不保存完整 IP。可选保存当日轮换盐的网络哈希，仅用于限流和滥用防护，不用于跨日追踪。

# 五、事件表

## 5.1 `product_events`

```sql
CREATE TABLE product_events (
  id TEXT PRIMARY KEY,
  event_id TEXT NOT NULL UNIQUE,
  actor_id TEXT NOT NULL REFERENCES actors(id) ON DELETE CASCADE,
  session_id TEXT NOT NULL REFERENCES product_sessions(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  occurred_at TEXT NOT NULL,
  received_at TEXT NOT NULL,
  role TEXT NOT NULL,
  page TEXT,
  script_id TEXT,
  act_id TEXT,
  node_id TEXT,
  knowledge_id TEXT,
  schema_version INTEGER NOT NULL,
  payload_json TEXT NOT NULL DEFAULT '{}',
  client_version TEXT,
  validation_status TEXT NOT NULL DEFAULT 'accepted',
  trace_id TEXT NOT NULL
);

CREATE INDEX idx_events_time ON product_events(occurred_at DESC);
CREATE INDEX idx_events_actor_time ON product_events(actor_id, occurred_at DESC);
CREATE INDEX idx_events_session_time ON product_events(session_id, occurred_at ASC);
CREATE INDEX idx_events_name_time ON product_events(name, occurred_at DESC);
CREATE INDEX idx_events_script_time ON product_events(script_id, occurred_at DESC);
CREATE INDEX idx_events_node ON product_events(script_id, node_id, occurred_at DESC);
```

字段提升规则：

- 高频筛选字段放独立列；
- 低频、事件特有字段进入 `payload_json`；
- payload 入库前经过事件 Schema 过滤；
- 不允许任意客户端 JSON 原样落库。

## 5.2 事件归档

MVP 不建设在线数仓。达到以下任一条件启动归档：

- 数据库文件超过 2 GB；
- `product_events` 超过 500 万条；
- 管理查询 P95 连续一周超过 500 ms。

归档流程：

1. 创建月度只读归档 SQLite；
2. 复制超过 12 个月的事件；
3. 校验条数和哈希；
4. 删除主库旧事件；
5. `VACUUM` 在维护窗口执行；
6. 管理端默认只查主库。

## 9.3 `audit_logs`

```sql
CREATE TABLE audit_logs (
  id TEXT PRIMARY KEY,
  admin_id TEXT REFERENCES admin_users(id) ON DELETE SET NULL,
  action TEXT NOT NULL,
  resource_type TEXT NOT NULL,
  resource_id TEXT,
  before_json TEXT,
  after_json TEXT,
  trace_id TEXT NOT NULL,
  network_hash TEXT,
  created_at TEXT NOT NULL
);

CREATE INDEX idx_audit_time ON audit_logs(created_at DESC);

CREATE INDEX idx_audit_resource ON audit_logs(resource_type, resource_id, created_at DESC);
```

审计 JSON 必须经过脱敏器：

- 移除密码哈希；
- 移除 Session Token；
- 移除 CSRF Secret；
- 移除 AI Key；
- 联系方式只保留是否存在；
- 用户自由文本只保存长度和摘要，正文留在业务表。

# 十、幂等表

```sql
CREATE TABLE idempotency_keys (
  scope TEXT NOT NULL,
  key TEXT NOT NULL,
  actor_id TEXT,
  request_hash TEXT NOT NULL,
  response_status INTEGER NOT NULL,
  response_json TEXT NOT NULL,

CREATE INDEX idx_idempotency_expiry ON idempotency_keys(expires_at);
```

# 十一、迁移文件规划

```text
server/db/migrations/
├─ 0001_core.sql
├─ 0002_events.sql
├─ 0003_admin_auth.sql
├─ 0004_ai_runs.sql
├─ 0005_feedback.sql
├─ 0006_wishes.sql
└─ 0007_indexes_and_retention.sql
```

每个迁移文件顶部写：

```sql
-- name: create_events
-- destructive: false
-- rollback: manual / not-required
```

SQLite 迁移回滚策略：

- 普通新增表/索引：代码回滚时可保留；
- 删列、改类型：禁止比赛前执行；
- 必须重建表时：先备份数据库，再创建新表、复制、校验、切换；
- 生产迁移前运行 `PRAGMA integrity_check`。

# 十二、Repository 接口

业务层不得直接散落 SQL。

```js
EventRepository.insertBatch(events)
EventRepository.list(filters)
EventRepository.getActorTimeline(actorId, filters)

AiRunRepository.create(run)
AiRunRepository.complete(id, result)

FeedbackRepository.create(input)
FeedbackRepository.update(id, patch, admin)

WishRepository.create(input)
WishRepository.vote(wishId, actorId)
WishRepository.changeStatus(id, transition, admin)
WishRepository.merge(sourceId, targetId, admin)

AdminRepository.findByUsername(username)
AdminSessionRepository.create(session)
AuditRepository.append(entry)
```

Repository 返回领域对象，不返回数据库行命名细节。

# 十三、备份与恢复

## 每日备份

使用 SQLite 在线备份命令或应用备份脚本，禁止直接复制正在写入的主文件而忽略 WAL。

备份命名：

```text
time-theater-20260804T230000Z.sqlite.gz
```

保留：

- 最近 7 天每日；
- 最近 4 周每周；
- 最近 6 个月每月。

## 恢复演练

每次大版本发布前：

1. 在临时目录恢复最新备份；
2. 执行 `integrity_check`；
3. 启动只读 API；
4. 抽查管理员、事件、愿望和审计；
5. 记录恢复耗时。

## 数据删除

按 actor 删除时：

- 删除/匿名化 actor 关联事件；
- 保留无法关联个人的聚合数据；
- 愿望公开内容可改为“匿名用户”；
- 管理员审计记录保留操作事实，移除用户标识；
- 删除动作写审计日志。
