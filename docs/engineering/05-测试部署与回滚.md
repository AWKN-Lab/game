# 四、安全验收

1. 仓库扫描不到 AI Key、管理员密码和生产 Cookie Secret；
2. 登录错误不区分用户名不存在或密码错误；
3. Cookie 为 HttpOnly、Secure、SameSite=Strict；
4. 管理写接口缺 CSRF 返回 403；
5. 普通用户不能访问 `/api/v1/admin/*`；
6. viewer 不能审核愿望或修改反馈；
7. 自由文本按纯文本输出，不执行 HTML；
8. SQL 注入字符串不能改变查询；
9. 反馈和愿望接口限流；
10. AI Provider 响应不能注入管理页面；
11. 日志不出现密码、Cookie、Token 和完整自由文本；
12. 数据导出、删除、合并写审计。

# 五、性能验收

使用本机/测试服务器完成：

| 场景 | 指标 |
|---|---|
| 事件批量写入 20 条 | P95 < 300 ms |
| 100 条事件时间线查询 | P95 < 500 ms |
| 热门愿望 20 条 | P95 < 300 ms |

- 20 并发事件批次；
- 10 并发愿望读取；
- 5 并发 AI 请求，验证限流和降级。

# 七、Nginx 设计

关键路由：

```nginx
root /www/wwwroot/awkn-lab/game/current;

location /api/ {
    proxy_pass http://127.0.0.1:3100;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_connect_timeout 3s;
    proxy_read_timeout 20s;
}

location /admin/ {
    try_files $uri $uri/ /admin/login.html;
}

location / {
    try_files $uri $uri/ =404;
}
```

要求：

- 生产 HTTPS；
- HTML 短缓存；
- 带 hash 的静态资源长缓存；
- `/shared/` 不可被 Web 访问；
- 数据库、`.env` 和日志不可暴露；
- 安全响应头由 Nginx 或 API 统一配置。

# 八、systemd 服务

示例单元：

```ini
[Unit]
Description=Time Theater API
After=network.target

[Service]
Type=simple
User=www
WorkingDirectory=/www/wwwroot/awkn-lab/game/current
EnvironmentFile=/www/wwwroot/awkn-lab/game/shared/.env
ExecStart=/usr/bin/node server/start.js
Restart=on-failure
RestartSec=3
NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

发布后：

```bash
systemctl daemon-reload
systemctl restart time-theater-api
systemctl is-active time-theater-api
curl -fsS http://127.0.0.1:3100/api/v1/health/ready
```

# 十一、回滚

## 11.1 代码回滚

触发条件：

- 主流程不可用；
- 5xx > 5%；
- 管理员无法登录；
- 数据写入错误；
- 严重隐私或权限问题。

步骤：

1. 将 `current` 指回上一发布目录；
2. 重启 API；
3. 验证 ready；
4. 验证首页和主剧本；
5. 记录事故和 traceId 范围。

目标：10 分钟内完成。

## 11.2 数据库回滚

原则：比赛前迁移尽量只新增表和字段，代码回滚后数据库可向前兼容。

禁止自动执行：

- 删除新表；
- 删除列；
- 恢复旧数据库覆盖新用户数据。

数据破坏时：

1. 停止 API 写入；
2. 复制当前损坏库作证据；
3. 评估增量恢复；
4. 只有确认无法修复时恢复备份；
5. 记录丢失时间窗口。
