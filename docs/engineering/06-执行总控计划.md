# 一、执行结论

现有工程任务已经足够详细，当前风险来自任务过多、基础设施顺序靠前、核心参赛体验可能被挤压。

本轮执行采用三条线：

1. **A 线｜参赛核心闭环**：教师导学卡、学生复盘卡、规则降级、五剧本稳定；
2. **B 线｜产品反馈闭环**：匿名事件、反馈、许愿池、管理员最小看板；
3. **C 线｜交付保障**：构建、测试、部署、备份、回滚、演示材料。

执行顺序固定为：

```text
先让项目可运行
→ 再跑通教师导学卡
→ 再跑通学生复盘卡
→ 冻结参赛主闭环
→ 再增加事件、许愿池和管理员后台
→ 最后部署与提交
```

A 线未通过验收，不得投入复杂后台统计、愿望合并算法、图表美化和扩展埋点。

# 三、执行前置动作

## 3.1 文档与代码分支分离

当前 PR #1 仅包含产品和工程文档。

正式开发前：

1. 审查并合并 PR #1；
2. 从最新 `main` 创建代码分支；
3. 不在文档分支直接堆叠运行代码。

建议代码分支：

```text
feat/ai-teaching-mvp
```

如果多人并行，可拆为：

```text
feat/m0-build-baseline
feat/m1-ai-lesson-card
feat/m2-learning-review
feat/m3-events-admin-wishes
feat/m4-release
```

## 3.2 建立执行看板

看板只使用五种状态：

```text
待开始
开发中
待联调
待验收
已完成
```

每项任务必须有：

- 唯一任务编号；
- 负责人；
- 开始时间；
- 截止时间；
- 前置依赖；
- 验收证据；
- 回滚说明。

## 3.3 建立功能开关

新增统一配置：

```js
window.FEATURE_FLAGS = {
  aiTeachingAssistant: true,
  eventTracking: false,
  wishPool: false,
  adminDashboard: false
};
```

要求：

- 新功能可以独立关闭；
- 关闭后原有五个剧本仍可运行；
- 生产故障时优先关开关，再判断是否回滚。

# 七、任务完成定义

一个任务只有同时满足以下条件才算完成：

1. 代码已提交；
2. 构建通过；
3. 自动测试通过；
4. 手工验收通过；
5. 有截图、日志或录屏证据；
6. 文档与实际实现一致；
7. 未增加未声明的数据采集；
8. 有独立关闭或回滚路径。

“代码写完”“页面能打开”“接口偶尔成功”都不算完成。

- 切换规则版；
- 关闭功能开关；
- 缩小字段；
- 使用静态模板；
- 移入 P1；
- 回滚到上一可运行版本。

## 8.2 AI 阻塞

- AI 接口不可用：规则版；
- 输出格式不稳定：强制 JSON Schema + 一次修复，仍失败则规则版；
- 响应过慢：15 秒超时；
- 内容错误：不展示，规则版；
- 成本异常：限制输入、输出和调用频率。

## 8.3 后端阻塞

- SQLite 锁：缩短事务、启用 busy timeout、检查连接生命周期；
- 管理员认证延迟：先完成单管理员登录，暂缓多角色；
- 事件积压：批量上传并限制队列；
- 数据迁移失败：恢复备份，代码保持旧结构；
- 管理后台未完成：保留最小表格页面，不做图表。

## 8.4 前端阻塞

- 新 SDK 影响剧本：立即关闭功能开关；
- 弹窗冲突：使用独立容器和命名空间；
- 移动端布局异常：优先保证按钮和内容可读，暂缓动画；
- 资源加载失败：降级为文字和背景色。
