# 一、定位：活人感是什么，不是什么

总 PRD V2.0 已确认：**核心是"选择被记住"，AI 只是表达层的手段**。因此本文档对"活人感"的定义是工程化的，不是玄学：

> **活人感 = 玩家的选择在 NPC 身上留下可观察的痕迹，且 NPC 的言行始终可被玩家理解。**

三条设计红线（继承总 PRD V2.0 设计边界，按 IP 技能门禁治理方式编号，违反任一条即阻断当次生成）：

1. **NPC-1 不替学生思考**：NPC 可以困惑、反驳、提条件，但不做价值评判式说教、不直接给"正确答案"。
2. **NPC-2 不越事实层**：NPC 输出以剧本知识库为唯一事实来源，与知识库冲突率必须为 0；引用记忆只允许 OBSERVED 与 INFERRED 级（见 4.1）。
3. **NPC-3 活人感不等于话多**：NPC 的"活"体现在记忆、态度变化和可解释行为上，不体现在输出长度或主动性上（逆水寒 AI NPC 过度主动翻车的教训：二测 5 万人中骚扰类交互 10 万+ 次，NPC 记忆被用于"翻旧账"式骚扰）。

# 二、方法论来源与取舍

本文档吸收以下内部资产与公开方法，并说明本项目"取什么、舍什么"（吸收登记纪律遵循 Forge 仓库 `COPY > MODIFY > ADAPT > NEW`）。

## 2.1 Forge 仓库：群体记忆与经验结构化（已吸收，内部资产）

出处：`AWKN-Lab/Forge` 仓库（枢密院产品线，与 Pri 共享 Memory OS / Agent OS / AWKN MCP 三大地基）。V1.0 曾引用一篇同名公开文章，经用户指认后以内部仓库为权威来源。

核心思想：智能体不更新模型权重，而是把经验片段结构化为"情境-意图-行动-结果"四元组加关键词标签，存入外部记忆库；记忆库按使用频率与有效性动态演化；吸收项必须登记来源与差异（`COPY > MODIFY > ADAPT > NEW` 纪律）。

**本项目取用：**

- **经验四元组**：NPC 记录玩家行为时采用统一结构 `{scene, player_intent, player_action, consequence}`，这是"选择被记住"的最小存储单元，也是生成回响（MOD-AI-05）的输入。
- **无权重更新**：本项目不微调模型，全部人格与记忆通过提示词 + 外部存储实现，与 Forge 的"不更新权重"路线一致，也符合零新增依赖的工程约束。
- **记忆库演化**：低频、低相关性的记忆条目在整理阶段衰减或合并，防止记忆表无限膨胀。
- **吸收登记纪律**：本文档第二节即按 Forge 的吸收治理格式登记各来源的"取用/舍去"，后续新增方法论来源照此办理。

**本项目舍去：**

- **群体广播**：多智能体共享记忆库面向 NPC 生态模拟。本项目 NPC 分属不同剧本、不同历史时期，跨剧本共享记忆会造成史实污染（唐朝官员"记得"民国事件），故**记忆严格按剧本隔离**，仅在"课堂多人模式"（V2.0 第三阶段）中考虑同剧本内 NPC 间的有限共享。

## 2.2 Engram：人格参数化的记忆编码（已吸收）

出处：Dua et al., *Engram: Personality-Parameterized Schema Memory for NPC Cognitive Diversity*, FDG '26（ACM，2026-08）。

核心发现：现有 NPC 记忆系统把人格只放在输出层过滤——两个 NPC 经历同一事件，形成的内部记忆相同，只是说话方式不同，人格沦为"表面滤镜"。Engram 把 OCEAN 人格向量参数化进记忆编码规则，让同一事件在不同 NPC 处形成**结构不同**的记忆（高神经质的守卫把 100% 事件标记为威胁，友善商人只标记 17%）。

**本项目取用：**

- **人格进入记忆层，而非只在输出层**：NPC 人设卡中的"偏爱"字段（如"多疑""重利"）不仅影响措辞，还影响**记什么、记多深**。实现上用轻量标签加权替代 Engram 的 Prolog 规则引擎（见 4.3 节）。
- **三层记忆结构**：会话记忆（滚动窗口）→ 中期摘要 → 长期关键记忆，与米哈游《星布谷地》公开的三层记忆方案相互印证，作为本项目记忆表设计的直接依据。
- **矛盾检查**：新信息与 NPC 已知事实冲突时，NPC 以角色身份处理（困惑、质疑、坚持旧见），而不是静默接受——这同时是活人感来源和事实一致性保障。

**本项目舍去：**

- **OCEAN 五维向量与 Prolog**：完整 OCEAN 参数化 + SWI-Prolog 矛盾验证对单剧本 3-5 个 NPC 的规模过重。改用**人格骨架卡 + 规则化标签权重**（见 4.2），保留"同一事件、不同记忆"的效果，不引入 Prolog 依赖。
- **人格动态漂移**：Engram 的威胁响应会临时修改人格向量。本项目 NPC 人格在单次剧本内保持稳定（学生需要可预测的角色），人格变化只发生在"信任状态"这一个显式维度上。

## 2.3 PICon：人设一致性三维评测（已吸收，用于验收）

出处：Kim et al., *PICon: A Multi-Turn Interrogation Framework for Evaluating Persona Agent Consistency*, arXiv:2603.25620（2026-05）。

核心发现：即使上下文里带着此前回答，多数人设智能体仍会在重测时改变核心设定；成对比较无法发现跨多轮累积的矛盾。该论文提出三维一致性：**内部一致性**（不与自己的话矛盾）、**外部一致性**（不与外部事实矛盾）、**重测一致性**（同样问题答案稳定）。

**本项目取用（作为验收方法，见第七节）：**

- **内部一致性**：NPC 不得与自己在本次剧本中的既有陈述矛盾（记忆表 + 知识库双重约束）。
- **外部一致性**：NPC 输出与剧本知识库冲突率 = 0（MOD-AI-04/06 既有验收，审稿人模块拦截）。
- **重测一致性**：同一学生在不同节点问 NPC 同一设定问题（如"现在是哪一年"），答案必须稳定。测试用例显式覆盖。

## 2.4 活人感行为设计（已吸收）

来源：TapTap《如何设计一个具备「活人感」的 NPC》（目标驱动 FSM、行为调制、不完美感知、战术协作四支柱）；SD 中文网人设提示词方法论（规则 + 示例、用行为代替形容词）；"人格骨架 × User 画像"双向自定义框架（价值/情绪/偏爱、主动与连续、关系质感）。

**本项目取用：**

- **目标驱动**：每个 NPC 人设卡必须写清"这个角色此刻想要什么"，NPC 回复围绕目标展开，不做无目的闲聊。
- **不完美感知**：NPC 只"知道"自己应该知道的事。学生提到 NPC 视角外的信息时，NPC 表现出困惑或追问，而不是全知式接话——这同时是防止 AI 越事实层的叙事化手段。
- **提示词写法**：人设卡用"行为 + 示例"代替形容词。不写"他很谨慎"，写"被问及未发生的事时，他先反问'你从哪里听来的？'"。每张人设卡至少 3 组正反示例。
- **状态连续性**：NPC 的态度由信任状态驱动且单调可解释（见 4.4），不出现无因的忽冷忽热。

## 2.5 Pri 仓库：Memory OS 记忆地基（已吸收，内部资产）

出处：`AWKN-Lab/Pri` 仓库（枢密院业务仓库，Relationship OS + Strategic Target + Decision + Action + Learning）。V1.0 曾按公开框架检索未果，经用户指认后以内部仓库为权威来源。

Memory OS 分层：`Source/Evidence/Claim/Lineage/Temporal/Conflict`（认知真值）→ `Memory Lifecycle/Retrieval/Context Ledger`（记忆生命周期与检索）→ `Outcome Evidence/Rule-Skill Evolution`（结果证据与规则演化）。

**本项目取用：**

- **证据分级**：记忆条目必须标注来源等级——`OBSERVED`（玩家行为或剧本知识库直接记录）、`INFERRED`（由行为推断，标明推理依据）、`UNKNOWN`（不知道，不编造）。NPC 引用记忆时只引用 OBSERVED 与 INFERRED，UNKNOWN 一律不出口。这直接落实"事实冲突率 = 0"的验收红线。
- **溯源（Lineage）**：每条关键记忆保留来源经验条目 ID（数据模型中的 `source_experience_id`），回响引用玩家行为时必须能回溯到具体事件，不允许凭空"记得"。
- **时间性（Temporal）**：记忆带剧情时间戳（第几幕第几节点），NPC 引用时能说清"上次在码头你……"，而不是含混的"以前"。
- **冲突处理（Conflict）**：新证据与既有记忆冲突时不静默覆盖，按 4.3 节矛盾检查以角色身份处理。
- **记忆生命周期**：写入 → 检索 → 演化（衰减/合并/升格）→ 归档，对应 4.1.3 节记忆演化设计。

**本项目舍去：**

- **Agent OS / AWKN MCP 整层**：Grant、Action Protocol、Connector 等面向多智能体生产系统，本项目单服务 + 单 LLM 接口的规模不需要；仅在第三阶段课堂多人模式需要动作协议时再评估。

## 2.6 OC 角色与叙事工厂技能（已吸收，内部技能）

出处：`AWKN-Lab/skills` 仓库 `L2_二级专精_公共专家/awkn-OC角色与叙事工厂`（五大子技能：灵魂圣经、90 秒钩子分镜、世界观伏笔账本、去 OOC 认知视野隔离、交互分支状态机与防吃书四联对账）。

**本项目取用：**

- **反差内核**：人格骨架卡增加"外在伪装面具 vs 内在核心执念"反差结构（见 4.2），NPC 的言行张力来自反差，不来自话术堆砌。
- **语言指纹**：每个 NPC 固定一组语言特征（口头禅、句式习惯、回避词），写入人设卡并在输出自检时校验——这是重测一致性的表达层保障。
- **信息雾（Information Fog）**：NPC 严格执行认知视野隔离，只"知道"自己视角内的事，防止未卜先知。与 2.4 的"不完美感知"互为印证，落地为 `knowledge_boundary` 字段必须映射到剧本知识库条目集合（4.2 既有约束）。
- **伏笔生命周期台账**：回响锚点采用 `PLANTED → RIPENING → HARVESTED` 三态管理（见 4.5）。埋下的选择（PLANTED）在后续幕次被提及（RIPENING），最终被回响正式回收（HARVESTED）；未回收的伏笔在剧本完结时清点，防止"挖坑不填"。
- **潜台词与动作反差**：NPC 输出风格约束——用动作反差和潜台词代替说明书式独白，写进 NPC 提示词规范。
- **防吃书四联对账**：多分支剧情合流前核对"位置/持有物/伤势/人际矩阵"四联状态（见 4.6），保证分支收敛零死胡同。

**本项目舍去：**

- **90 秒漫剧分镜**：面向短视频漫剧节奏，与课堂剧本的节奏体系不同，不引入。
- **机械门禁 CLI**：OC 技能的确定性门禁脚本模式值得借鉴，但本项目验收走测试用例 + 事件统计（第七节），不另建门禁工具。

## 2.7 IP 形象设计技能（已吸收，内部技能）

出处：`AWKN-Lab/skills` 仓库 `IP形象设计`（2D 主播形象工作流：人物圣经、一句话反差 + 可重复钩子、三视图、表情库、硬门禁）。

**本项目取用：**

- **人物圣经 = 唯一事实源**：NPC 人设卡即"人物圣经"，所有生成与修改先写回圣经再派发；每次纠正先入卡再生效，杜绝"提示词里一套、卡里另一套"。
- **一句话反差 + 可重复钩子**：每个 NPC 必须能用一句话说清反差（外表一句 + 内在相反一句），并有一个可重复的识别钩子（口头禅、标志性动作或随身物件）。钩子进人设卡，NPC 对话与回响均可引用——这是"记得住"的最小单位。
- **作废标记与定期清脏**：人设卡与记忆条目作废时显式标记，不留两可；剧本大改后通读清脏（对应 4.1.3 记忆演化的合并归档）。
- **表情库分档**：NPC 情绪表达用固定小库（常用 6 档：平静、追问、警惕、软化、激动、克制），需要更细情绪时从扩展库取，且扩展表情不得改变人设核心特征——防止 AI 为表达情绪而漂移人设。
- **硬门禁编号化**：本文档三条设计红线升级为编号门禁（见第三节），与 IP 技能 IP-1~IP-7 的治理方式对齐。

**本项目舍去：**

- **三视图 / 生图流程**：面向视觉资产生产，NPC 文本对话不涉及；若后续做 NPC 立绘或 IP 联名（总 PRD 第三步 +IP），届时按该技能单独立项。

# 三、总体架构

```text
学生自由输入
  │
  ▼
[内容安全检查]（既有能力，unsafe 直接拦截）
  │
  ▼
[历史审稿人 MOD-AI-06]（旁路）
  │  verdict: pass / anachronism / factual_error / unsafe
  ▼
[NPC 对话编排器 MOD-AI-04]
  ├─ 1. 组装上下文：人设卡 + 信任状态 + 剧情节点 + 玩家选择历史
  ├─ 2. 记忆检索：会话窗口 + 中期摘要 + 关键记忆（人格加权）
  ├─ 3. 矛盾预检：新输入 vs NPC 已知事实（规则层，不调 AI）
  ├─ 4. 调用 LLM（OpenAI 兼容接口，qwen-plus，超时 15s）
  └─ 5. 输出校验：结构 + 人设红线 + 事实冲突标记
  │
  ▼
[记忆写入]（异步，失败不阻塞对话）
  ├─ 经验四元组 → 会话记忆
  ├─ 每 N 轮 → 中期摘要（人格偏置）
  └─ 高权重事件 → 关键记忆 + 事实条目
  │
  ▼
[回响生成 MOD-AI-05]（后续幕次，按回响锚点触发）
  └─ 失败降级：规则版模板库
```

三条硬性降级路径（任何一条失败，剧情不中断）：

1. LLM 超时（15s）或结构校验失败 → NPC 预设台词池；
2. 审稿人不可用 → 全部输入按 `pass` 处理，但记录事件供教师端事后查看；
3. 记忆写入失败 → 本轮对话继续，记忆缺失记入日志。

# 四、核心设计

## 4.1 记忆模型：三层 + 四元组

### 4.1.1 经验四元组（FORGE）

每次 NPC 与学生交互后，异步写入一条结构化经验：

```json
{
  "script_id": "xinhai_revolution",
  "npc_id": "npc_lin_wenqing",
  "scene": "act2_dock_night",
  "player_intent": "persuade",
  "player_action": "chose_hide_newspaper",
  "consequence": "trust+1",
  "tags": ["信任上升", "报纸", "第二幕"],
  "weight": 0.7,
  "evidence": "OBSERVED",
  "story_time": "act2_node3"
}
```

**证据分级**（Pri Memory OS）：`evidence` 字段取 `OBSERVED`（玩家行为或知识库直接记录）/ `INFERRED`（推断，需附推理说明）/ `UNKNOWN`（不写入）。`story_time` 为剧情时间戳，供 NPC 引用时说清"上次在码头"。

### 4.1.2 三层记忆（Engram / 星布谷地方案）

| 层 | 存储 | 生命周期 | 用途 |
|---|---|---|---|
| 会话记忆 | 最近 7 轮对话原文 | 当前对话 | 保证本轮连贯（对应 PICon 内部一致性） |
| 中期摘要 | 每 5 轮被逐出窗口的内容，生成两句话摘要，带人格偏置标签 | 当前剧本 | 跨幕次态度延续 |
| 关键记忆 | 人格加权得分前 25% 的事件，升格为事实条目 | 持久（按剧本） | 生成回响、支撑"翻旧账"式引用 |

**人格偏置**：摘要与升格时，按人设卡的"偏爱"标签调整权重。例：多疑 NPC 对"隐瞒/试探"类事件权重 ×1.5，重利 NPC 对"利益相关"事件权重 ×1.5。同一事件在不同 NPC 处形成不同深浅的记忆——这是"同一事件、不同记忆"的轻量实现。

### 4.1.3 记忆演化（FORGE）

- 定期（剧本存档时）合并语义重复条目；
- 权重低于阈值且超过 30 天未命中的条目归档；
- 关键记忆被回响引用一次，权重 +0.1（被记住的选择更容易被再次提起）。

## 4.2 人格骨架卡

替代 OCEAN 向量的轻量结构，存于剧本元数据（由剧本内容系统维护，对应 CMP-02）：

```yaml
npc_id: npc_lin_wenqing
name: 林文清
role: 报馆主笔
contrast_core:                          # 反差内核（OC 技能 NS-1）
  mask: 温和守旧的读书人                # 外在伪装面具
  obsession: 查清报馆被封的真相          # 内在核心执念
hook: "风声？我天天在风声里吃饭。"        # 可重复识别钩子（IP 技能）
language_fingerprint:                   # 语言指纹（OC 技能）
  catchphrase: ["风声", "字比人活得久"]
  avoid: ["网络语", "解释性独白"]
goal: 查清报馆被封的真相，同时保护家人      # 目标驱动
values: [求真, 护短]                        # 价值
emotion_baseline: 克制、偶尔激烈            # 情绪
emotion_library: [平静, 追问, 警惕, 软化, 激动, 克制]  # 表情库 6 档（IP 技能）
preferences:                                # 偏爱（记忆偏置依据）
  - 记性好：对"被欺骗"类事件权重 ×1.5
  - 对读书人态度软化
knowledge_boundary: 只知道报馆与码头一带的事  # 信息雾边界（OC 技能 NS-4）
speech_examples:                            # 行为代替形容词，≥3 组
  - 问: "外面风声很紧吧？" 答: "风声？我天天在风声里吃饭。"
  - （被追问未公开消息时）先反问来源，再决定是否回答
  - （谈到家人时）转移话题，手指敲桌面
trust_triggers:                             # 信任状态变化规则
  - 帮助隐瞒 → +1
  - 直接询问家人 → -1
```

**约束**：人设卡即"人物圣经"，是唯一事实源——所有提示词组装、修改与纠正先写回卡片再生效（IP 技能纪律）；卡片由人工（历史审稿人协助）编写与审核，AI 不生成人设卡；`knowledge_boundary` 必须能映射到剧本知识库的具体条目集合；扩展情绪不得改变 `contrast_core` 与 `language_fingerprint`。

## 4.3 矛盾检查（规则层，不调 AI）

Engram 用 Prolog 做形式化矛盾验证，本项目降级为规则层：

- NPC 事实条目（来自知识库 + 关键记忆升格）维护为 `{subject, predicate, object}` 三元组集合；
- 学生输入经审稿人标记 `factual_error` 时，NPC 以角色身份回应（困惑、纠正、坚持旧见），不显示判定卡片（MOD-AI-06 既有规则）；
- NPC 自身输出前，做一次关键词级自检：输出中出现的年份、人名、地名若与事实条目冲突，触发重试一次，仍冲突则降级为规则版回复。

## 4.4 信任状态：唯一的"人格动态"维度

- 信任值由 `trust_triggers` 规则驱动，单调可解释，学生可在剧情中观察到变化（对应总 PRD"人物信任可见化"支柱）；
- 信任决定 NPC 回复类型：正常对话 / 拒绝（信任不足）/ 提出条件（MOD-AI-04 输出契约）；
- NPC 记忆可以"翻旧账"（引用关键记忆），但**只用于剧情推进**（如提出条件时引用学生此前的选择），不用于主动骚扰或重复指责——逆水寒教训的直接规避。

## 4.5 回响生成（MOD-AI-05）

- 输入：玩家选择历史（经验四元组）+ 回响锚点 + 规则版模板；
- **伏笔生命周期台账**（OC 技能 NS-3）：回响锚点三态管理——
  - `PLANTED`：玩家做出选择，经验四元组写入，锚点登记；
  - `RIPENING`：后续幕次的 NPC 对话提及该选择（引用须带 `story_time`，说清"上次在码头"）；
  - `HARVESTED`：回响正式回收该选择，写入事件 `echo_referenced`；
  - 剧本完结时清点未 `HARVESTED` 的锚点，防止"挖坑不填"。
- AI 版要求：一至两句，必须引用至少一个具体玩家行为（可回溯到 `source_experience_id`），且符合 NPC 语言指纹；
- 生成失败或超时 → 按锚点从模板库选取，不出现占位文案。

## 4.6 剧情状态对账（防吃书，OC 技能 NS-5）

多分支剧情合流或 NPC 引用历史前，核对四联状态表，任一不一致即阻断引用并降级为规则版：

| 维度 | 校验内容 | 数据来源 |
|---|---|---|
| 位置 | NPC 与学生当前所在剧情节点一致 | 剧情引擎状态 |
| 持有物 | NPC 提及的物品确实在学生/NPC 手上 | 剧情状态变量 |
| 伤势/损失 | 已发生的损失不被"忘记"或凭空恢复 | 事件记录 |
| 人际矩阵 | NPC 对学生及其他角色的态度与信任值一致 | 信任状态 + 关键记忆 |

该对账在规则层完成（不调 AI），是"分支收敛零死胡同"的工程保障；对账失败写入事件日志供教师端排查。

新增表（迁移脚本遵循 ENG-03 规范）：

```sql
-- NPC 人设卡（剧本元数据的一部分，随剧本版本管理）
CREATE TABLE npc_persona (

  script_id TEXT NOT NULL,

  consequence TEXT,
  tags TEXT,                          -- JSON array
  weight REAL DEFAULT 0.5,
  created_at TEXT NOT NULL
);

CREATE TABLE npc_key_memory (
  id INTEGER PRIMARY KEY AUTOINCREMENT,

  npc_id TEXT NOT NULL,
  fact_json TEXT NOT NULL,            -- {subject, predicate, object}

  weight REAL DEFAULT 0.5,
  created_at TEXT NOT NULL
);

CREATE TABLE npc_memory_summary (
  id INTEGER PRIMARY KEY AUTOINCREMENT,

);
```

# 七、验收指标

| 指标 | 目标 | 测量方法 |
|---|---|---|
| 事实冲突率 | = 0 | 审稿人拦截后，NPC 输出与剧本知识库比对（MOD-AI-04/06 既有验收） |
| 内部一致性 | 抽检无自相矛盾 | 每剧本准备 20 条跨轮次追问用例（PICon 方法） |
| 重测一致性 | 核心设定问题答案 100% 稳定 | 同一设定问题在不同节点重复提问（PICon 方法） |
| 人设违背率 | < 3% | 教师抽检 + 事件日志统计 |
| 自由输入参与率 | ≥ 30% | 事件 `npc_dialogue_started` |
| 对话轮数中位数 | ≥ 3 | 事件统计 |
| AI 降级率 | < 0.5%，且降级时 100% 使用规则版 | 事件 `npc_dialogue_degraded` |
| P95 响应延迟 | ≤ 15s（超时即降级） | 服务端计时 |
| 单 NPC 日均 token | 上限随部署环境设定并监控 | 用量日志 |
| 回响相关率 | 100% | AI 版与规则版均须引用玩家行为 |

# 九、风险与边界

1. **记忆膨胀**：经验四元组按剧本累积，需在存档时执行合并与归档（4.1.3），否则长剧本下检索质量下降。
2. **人格偏置误伤**：标签加权依赖人设卡质量，人设卡编写纳入剧本审核流程（历史审稿人可辅助校对边界）。
3. **课堂延迟敏感**：15s 超时对课堂节奏已偏长，实现上优先压缩上下文（三层记忆按需检索），而非加大超时。
4. **内部资产同步**：Forge/Pri 仓库与 OC/IP 技能仍在演进，本文档吸收的是 2026-11-27 时点的内容；上游有实质变更时按 Forge 吸收登记纪律评估是否跟进，不自动同步。
5. **门禁误伤**：NPC-1~NPC-3 编号门禁与四联对账都在规则层阻断生成，阈值过严会造成频繁降级；上线初期放宽为"记录 + 抽检"，稳定后再收紧为硬阻断。
