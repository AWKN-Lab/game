# 一、定位：活人感是什么，不是什么

总 PRD V2.0 已确认：**核心是"选择被记住"，AI 只是表达层的手段**。因此本文档对"活人感"的定义是工程化的，不是玄学：

> **活人感 = 玩家的选择在 NPC 身上留下可观察的痕迹，且 NPC 的言行始终可被玩家理解。**

三条设计红线（继承总 PRD V2.0 设计边界）：

1. **NPC 不替学生思考**：NPC 可以困惑、反驳、提条件，但不做价值评判式说教、不直接给"正确答案"。
2. **AI 不越事实层**：NPC 输出以剧本知识库为唯一事实来源，与知识库冲突率必须为 0。
3. **活人感不等于话多**：NPC 的"活"体现在记忆、态度变化和可解释行为上，不体现在输出长度或主动性上（逆水寒 AI NPC 过度主动翻车的教训：二测 5 万人中骚扰类交互 10 万+ 次，NPC 记忆被用于"翻旧账"式骚扰）。

# 二、方法论来源与取舍

本文档吸收以下公开方法与论文，并说明本项目"取什么、舍什么"。

## 2.1 FORGE：群体记忆与经验结构化（已吸收）

出处：《FORGE 架构解析：无权重更新的 AI 智能体群体记忆与自我进化系统》（CSDN，2026-08）。

核心思想：智能体不更新模型权重，而是把经验片段结构化为"情境-意图-行动-结果"四元组加关键词标签，存入外部记忆库；其他智能体检索借鉴；记忆库按使用频率与有效性动态演化。

**本项目取用：**

- **经验四元组**：NPC 记录玩家行为时采用统一结构 `{scene, player_intent, player_action, consequence}`，这是"选择被记住"的最小存储单元，也是生成回响（MOD-AI-05）的输入。
- **无权重更新**：本项目不微调模型，全部人格与记忆通过提示词 + 外部存储实现，与 FORGE 的"不更新权重"路线一致，也符合零新增依赖的工程约束。
- **记忆库演化**：低频、低相关性的记忆条目在整理阶段衰减或合并，防止记忆表无限膨胀。

**本项目舍去：**

- **群体广播**：FORGE 的多智能体共享记忆库面向 NPC 生态模拟。本项目 NPC 分属不同剧本、不同历史时期，跨剧本共享记忆会造成史实污染（唐朝官员"记得"民国事件），故**记忆严格按剧本隔离**，仅在"课堂多人模式"（V2.0 第三阶段）中考虑同剧本内 NPC 间的有限共享。

## 2.2 Engram：人格参数化的记忆编码（已吸收）

出处：Dua et al., *Engram: Personality-Parameterized Schema Memory for NPC Cognitive Diversity*, FDG '26（ACM，2026-08）。

核心发现：现有 NPC 记忆系统把人格只放在输出层过滤——两个 NPC 经历同一事件，形成的内部记忆相同，只是说话方式不同，人格沦为"表面滤镜"。Engram 把 OCEAN 人格向量参数化进记忆编码规则，让同一事件在不同 NPC 处形成**结构不同**的记忆（高神经质的守卫把 100% 事件标记为威胁，友善商人只标记 17%）。

**本项目取用：**

- **人格进入记忆层，而非只在输出层**：NPC 人设卡中的"偏爱"字段（如"多疑""重利"）不仅影响措辞，还影响**记什么、记多深**。实现上用轻量标签加权替代 Engram 的 Prolog 规则引擎（见 4.3 节）。
- **三层记忆结构**：会话记忆（滚动窗口）→ 中期摘要 → 长期关键记忆，与米哈游《星布谷地》公开的三层记忆方案相互印证，作为本项目记忆表设计的直接依据。
- **矛盾检查**：新信息与 NPC 已知事实冲突时，NPC 以角色身份处理（困惑、质疑、坚持旧见），而不是静默接受——这同时是活人感来源和事实一致性保障。

**本项目舍去：**

- **OCEAN 五维向量与 Prolog**：完整 OCEAN 参数化 + SWI-Prolog 矛盾验证对单剧本 3-5 个 NPC 的规模过重。改用**人格骨架卡 + 规则化标签权重**（见 4.2），保留"同一事件、不同记忆"的效果，不引入 Prolog 依赖。
- **人格动态漂移**：Engram 的威胁响应会临时修改人格向量。本项目 NPC 人格在单次剧本内保持稳定（学生需要可预测的角色），人格变化只发生在"信任状态"这一个显式维度上。

## 2.3 PICon：人设一致性三维评测（已吸收，用于验收）

出处：Kim et al., *PICon: A Multi-Turn Interrogation Framework for Evaluating Persona Agent Consistency*, arXiv:2603.25620（2026-05）。

核心发现：即使上下文里带着此前回答，多数人设智能体仍会在重测时改变核心设定；成对比较无法发现跨多轮累积的矛盾。该论文提出三维一致性：**内部一致性**（不与自己的话矛盾）、**外部一致性**（不与外部事实矛盾）、**重测一致性**（同样问题答案稳定）。

**本项目取用（作为验收方法，见第七节）：**

- **内部一致性**：NPC 不得与自己在本次剧本中的既有陈述矛盾（记忆表 + 知识库双重约束）。
- **外部一致性**：NPC 输出与剧本知识库冲突率 = 0（MOD-AI-04/06 既有验收，审稿人模块拦截）。
- **重测一致性**：同一学生在不同节点问 NPC 同一设定问题（如"现在是哪一年"），答案必须稳定。测试用例显式覆盖。

## 2.4 活人感行为设计（已吸收）

来源：TapTap《如何设计一个具备「活人感」的 NPC》（目标驱动 FSM、行为调制、不完美感知、战术协作四支柱）；SD 中文网人设提示词方法论（规则 + 示例、用行为代替形容词）；"人格骨架 × User 画像"双向自定义框架（价值/情绪/偏爱、主动与连续、关系质感）。

**本项目取用：**

- **目标驱动**：每个 NPC 人设卡必须写清"这个角色此刻想要什么"，NPC 回复围绕目标展开，不做无目的闲聊。
- **不完美感知**：NPC 只"知道"自己应该知道的事。学生提到 NPC 视角外的信息时，NPC 表现出困惑或追问，而不是全知式接话——这同时是防止 AI 越事实层的叙事化手段。
- **提示词写法**：人设卡用"行为 + 示例"代替形容词。不写"他很谨慎"，写"被问及未发生的事时，他先反问'你从哪里听来的？'"。每张人设卡至少 3 组正反示例。
- **状态连续性**：NPC 的态度由信任状态驱动且单调可解释（见 4.4），不出现无因的忽冷忽热。

## 2.5 PRI：未找到公开出处（待用户补充）

多轮检索（"PRI framework agent"、"PRI NPC 记忆"、"PRI persona"）未找到名为 PRI 的公开 AI/NPC 框架。唯一同名项目是 Devpost 上的 "PRI — Production Resilience Intelligence"（影视排期数字孪生，与 NPC 无关）。

已按最接近的公开方法论吸收了人格一致性、记忆分层与行为设计（见 2.2-2.4）。**若 PRI 指其他出处（论文、博客、内部资料），请提供链接，本文档将补充吸收。**

# 三、总体架构

```text
学生自由输入
  │
  ▼
[内容安全检查]（既有能力，unsafe 直接拦截）
  │
  ▼
[历史审稿人 MOD-AI-06]（旁路）
  │  verdict: pass / anachronism / factual_error / unsafe
  ▼
[NPC 对话编排器 MOD-AI-04]
  ├─ 1. 组装上下文：人设卡 + 信任状态 + 剧情节点 + 玩家选择历史
  ├─ 2. 记忆检索：会话窗口 + 中期摘要 + 关键记忆（人格加权）
  ├─ 3. 矛盾预检：新输入 vs NPC 已知事实（规则层，不调 AI）
  ├─ 4. 调用 LLM（OpenAI 兼容接口，qwen-plus，超时 15s）
  └─ 5. 输出校验：结构 + 人设红线 + 事实冲突标记
  │
  ▼
[记忆写入]（异步，失败不阻塞对话）
  ├─ 经验四元组 → 会话记忆
  ├─ 每 N 轮 → 中期摘要（人格偏置）
  └─ 高权重事件 → 关键记忆 + 事实条目
  │
  ▼
[回响生成 MOD-AI-05]（后续幕次，按回响锚点触发）
  └─ 失败降级：规则版模板库
```

三条硬性降级路径（任何一条失败，剧情不中断）：

1. LLM 超时（15s）或结构校验失败 → NPC 预设台词池；
2. 审稿人不可用 → 全部输入按 `pass` 处理，但记录事件供教师端事后查看；
3. 记忆写入失败 → 本轮对话继续，记忆缺失记入日志。

# 四、核心设计

## 4.1 记忆模型：三层 + 四元组

### 4.1.1 经验四元组（FORGE）

每次 NPC 与学生交互后，异步写入一条结构化经验：

```json
{
  "script_id": "xinhai_revolution",
  "npc_id": "npc_lin_wenqing",
  "scene": "act2_dock_night",
  "player_intent": "persuade",
  "player_action": "chose_hide_newspaper",
  "consequence": "trust+1",
  "tags": ["信任上升", "报纸", "第二幕"],
  "weight": 0.7
}
```

### 4.1.2 三层记忆（Engram / 星布谷地方案）

| 层 | 存储 | 生命周期 | 用途 |
|---|---|---|---|
| 会话记忆 | 最近 7 轮对话原文 | 当前对话 | 保证本轮连贯（对应 PICon 内部一致性） |
| 中期摘要 | 每 5 轮被逐出窗口的内容，生成两句话摘要，带人格偏置标签 | 当前剧本 | 跨幕次态度延续 |
| 关键记忆 | 人格加权得分前 25% 的事件，升格为事实条目 | 持久（按剧本） | 生成回响、支撑"翻旧账"式引用 |

**人格偏置**：摘要与升格时，按人设卡的"偏爱"标签调整权重。例：多疑 NPC 对"隐瞒/试探"类事件权重 ×1.5，重利 NPC 对"利益相关"事件权重 ×1.5。同一事件在不同 NPC 处形成不同深浅的记忆——这是"同一事件、不同记忆"的轻量实现。

### 4.1.3 记忆演化（FORGE）

- 定期（剧本存档时）合并语义重复条目；
- 权重低于阈值且超过 30 天未命中的条目归档；
- 关键记忆被回响引用一次，权重 +0.1（被记住的选择更容易被再次提起）。

## 4.2 人格骨架卡

替代 OCEAN 向量的轻量结构，存于剧本元数据（由剧本内容系统维护，对应 CMP-02）：

```yaml
npc_id: npc_lin_wenqing
name: 林文清
role: 报馆主笔
goal: 查清报馆被封的真相，同时保护家人      # 目标驱动
values: [求真, 护短]                        # 价值
emotion_baseline: 克制、偶尔激烈            # 情绪
preferences:                                # 偏爱（记忆偏置依据）
  - 记性好：对"被欺骗"类事件权重 ×1.5
  - 对读书人态度软化
knowledge_boundary: 只知道报馆与码头一带的事  # 不完美感知边界
speech_examples:                            # 行为代替形容词，≥3 组
  - 问: "外面风声很紧吧？" 答: "风声？我天天在风声里吃饭。"
  - （被追问未公开消息时）先反问来源，再决定是否回答
trust_triggers:                             # 信任状态变化规则
  - 帮助隐瞒 → +1
  - 直接询问家人 → -1
```

**约束**：人设卡由人工（历史审稿人协助）编写与审核，AI 不生成人设卡；`knowledge_boundary` 必须能映射到剧本知识库的具体条目集合。

## 4.3 矛盾检查（规则层，不调 AI）

Engram 用 Prolog 做形式化矛盾验证，本项目降级为规则层：

- NPC 事实条目（来自知识库 + 关键记忆升格）维护为 `{subject, predicate, object}` 三元组集合；
- 学生输入经审稿人标记 `factual_error` 时，NPC 以角色身份回应（困惑、纠正、坚持旧见），不显示判定卡片（MOD-AI-06 既有规则）；
- NPC 自身输出前，做一次关键词级自检：输出中出现的年份、人名、地名若与事实条目冲突，触发重试一次，仍冲突则降级为规则版回复。

## 4.4 信任状态：唯一的"人格动态"维度

- 信任值由 `trust_triggers` 规则驱动，单调可解释，学生可在剧情中观察到变化（对应总 PRD"人物信任可见化"支柱）；
- 信任决定 NPC 回复类型：正常对话 / 拒绝（信任不足）/ 提出条件（MOD-AI-04 输出契约）；
- NPC 记忆可以"翻旧账"（引用关键记忆），但**只用于剧情推进**（如提出条件时引用学生此前的选择），不用于主动骚扰或重复指责——逆水寒教训的直接规避。

## 4.5 回响生成（MOD-AI-05）

- 输入：玩家选择历史（经验四元组）+ 回响锚点 + 规则版模板；
- AI 版要求：一至两句，必须引用至少一个具体玩家行为（"相关率 100%"验收）；
- 生成失败或超时 → 按锚点从模板库选取，不出现占位文案；
- 触发写入事件 `echo_referenced`。

# 五、数据模型（node:sqlite，WAL）

新增表（迁移脚本遵循 ENG-03 规范）：

```sql
-- NPC 人设卡（剧本元数据的一部分，随剧本版本管理）
CREATE TABLE npc_persona (
  npc_id TEXT PRIMARY KEY,
  script_id TEXT NOT NULL,
  persona_json TEXT NOT NULL,        -- 4.2 节骨架卡
  version INTEGER NOT NULL
);

-- 经验四元组（会话记忆 + 中期来源）
CREATE TABLE npc_experience (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  script_id TEXT NOT NULL,
  npc_id TEXT NOT NULL,
  scene TEXT NOT NULL,
  player_intent TEXT,
  player_action TEXT,
  consequence TEXT,
  tags TEXT,                          -- JSON array
  weight REAL DEFAULT 0.5,
  created_at TEXT NOT NULL
);

-- 关键记忆（升格后的事实条目）
CREATE TABLE npc_key_memory (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  script_id TEXT NOT NULL,
  npc_id TEXT NOT NULL,
  fact_json TEXT NOT NULL,            -- {subject, predicate, object}
  source_experience_id INTEGER,
  weight REAL DEFAULT 0.5,
  created_at TEXT NOT NULL
);

-- 中期摘要
CREATE TABLE npc_memory_summary (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  script_id TEXT NOT NULL,
  npc_id TEXT NOT NULL,
  summary TEXT NOT NULL,
  bias_tags TEXT,                     -- 人格偏置标签
  created_at TEXT NOT NULL
);
```

索引：`(script_id, npc_id, created_at)`；所有查询带 `script_id` 条件，保证剧本间记忆隔离。

# 六、接口与工程约束

遵循 ENG-07 ADR：Node.js 内置 `node:http` + `node:sqlite`，**不新增 npm 依赖**；AI 走 OpenAI 兼容接口（`AI_MODEL=qwen-plus`，密钥仅服务端）。

新增/扩展接口（契约细节随实现补充至 ENG-02）：

| 接口 | 模块 | 说明 |
|---|---|---|
| `POST /api/v1/npc/dialogue` | MOD-AI-04 | 自由输入对话，返回回复 + 类型标记 |
| `POST /api/v1/npc/echo` | MOD-AI-05 | 按锚点生成回响 |
| `POST /api/v1/npc/fact-check` | MOD-AI-06 | 审稿人判定（旁路） |

统一超时 15s；LLM 调用失败一律降级，不重试超过 1 次（重试会拖垮课堂节奏）。

新增事件（对应总 PRD V2.0 八个新事件）：`npc_dialogue_started`、`npc_dialogue_completed`、`npc_dialogue_degraded`、`echo_generated`、`echo_referenced`、`fact_check_flagged` 等按总 PRD 埋点规范落库。

# 七、验收指标

| 指标 | 目标 | 测量方法 |
|---|---|---|
| 事实冲突率 | = 0 | 审稿人拦截后，NPC 输出与剧本知识库比对（MOD-AI-04/06 既有验收） |
| 内部一致性 | 抽检无自相矛盾 | 每剧本准备 20 条跨轮次追问用例（PICon 方法） |
| 重测一致性 | 核心设定问题答案 100% 稳定 | 同一设定问题在不同节点重复提问（PICon 方法） |
| 人设违背率 | < 3% | 教师抽检 + 事件日志统计 |
| 自由输入参与率 | ≥ 30% | 事件 `npc_dialogue_started` |
| 对话轮数中位数 | ≥ 3 | 事件统计 |
| AI 降级率 | < 0.5%，且降级时 100% 使用规则版 | 事件 `npc_dialogue_degraded` |
| P95 响应延迟 | ≤ 15s（超时即降级） | 服务端计时 |
| 单 NPC 日均 token | 上限随部署环境设定并监控 | 用量日志 |
| 回响相关率 | 100% | AI 版与规则版均须引用玩家行为 |

# 九、风险与边界

1. **记忆膨胀**：经验四元组按剧本累积，需在存档时执行合并与归档（4.1.3），否则长剧本下检索质量下降。
