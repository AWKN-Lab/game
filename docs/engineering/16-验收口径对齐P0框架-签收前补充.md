# ENG-16｜验收口径对齐 P0 框架——W00 签收前补充（供老板签收 D1–D5 时一并确认）

> 本文逐条核对 ENG-14 验收口径与新战略的对齐情况，列出三处缺口与建议补充；不阻塞 W03–W05 开发启动，口径确认可并行。

## 2. 缺口 A：W06 建议新增 T15 反事实测试

- **判据**：对五剧本逐一执行——屏蔽/移除全部 evidence 与 knowledge 节点内容后，若玩家仍可无障碍通关并拿到全部关键收集品与结业测验及格，则该剧本 FAIL。
- **实施**：先做半自动（脚本注入开关跳过证据内容 + 人工通关走查），沉淀为 `scripts/validate-counterfactual.mjs` 静态检查（关键剧情门是否引用证据交互状态）作为长期门禁；建议挂在 W06 放行清单，不阻塞 W03–W05。
- **边界**：本测试验收「历史是否承重」，与 W07 的「反事实三变体」（教学内容设计）是两回事，勿混用。

## 3. 缺口 B：W05 看板建议增加北极星口径（草案待老板确认）

33 事件中可作候选信号的：`script.choice`、`script.card`（主动用卡）、`npc.free_input_submitted`（主动提问）、`npc.dialogue_started`、`quiz.answer(correct)`、`script.ending`。

**草案口径**（自主场景，排除课堂 `director.*` 会话）：
- 分母 = `script.start` 的 attempt 数（沿用 W05「合法开始 cohort」）；
- 分子 = attempt 内发生 ≥N 次**自主发起**探索事件（主动用卡/主动提问/主动查看知识点），且结业测验完成；
- 「有效」= 测验正确或独立测验（未见材料）答对。

**关键缺口——现有事件分不清「自主」与「剧情强制」**：`script.evidence_open`/`script.knowledge_open` 由剧本节点强制触发，不能当自主信号；`script.choice` 是剧情必经选择。若直接用这些事件计算，P0 数据会虚高或白采。
**建议**：W04 事件桥实施时为探索类事件补 `initiator: 'player' | 'script'` 字段（或新增显式自主探索事件），列入 W05 字段冻结清单；N 值与「有效」阈值由老板在签收时拍板，避免实施后返工。
