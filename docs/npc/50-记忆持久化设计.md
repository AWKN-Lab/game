# NPC 记忆持久化设计——吸收自 AWKN-Memory-OS

> 对应 `server/services/npc-chat-service.js` 与 `server/db/database.js` 中 `npc_states` / `npc_memory_records` 两表。
> 吸收来源：`AWKN-Lab/AWKN-Memory-OS` 仓库 `docs/10-memory-os-absorption-spec/spec.md`（MOS-ABSORB-SPEC-001）。
> 遵守其总体原则第 7 条：不复制源码、不引入第二套记忆本体，按本仓库架构重新实现。

## 能力映射

| Memory OS 概念 | 本仓库落地 | 位置 |
|---|---|---|
| Tier 状态机 T0—T4 | 简化为 T1_SESSION（会话暂存）→ T3_ACTIVE（活跃关键记忆）→ T4_ARCHIVE（归档）；超出 7 轮窗口的旧轮次归档不删除，保留可追溯证据 | `recordTurn` 逐出逻辑 |
| Evidence / source refs | 关键记忆携带 `source_refs_json`（来源轮次 memory_id）与 `story_time`，引用时说清"上次"是什么时候 | `promoteKeyMemory` |
| Active View（可重建投影） | `getActiveView` 只返回 ACTIVE 记录：会话窗口 ≤7 轮 + 活跃关键记忆；归档与废止记录不进入提示词 | `getActiveView` |
| 内容哈希幂等 | `content_hash` = sha256(role\|content)（会话）或 sha256(key\|content)（关键记忆）；同哈希不重复入库，返回原 memory_id | `recordTurn` / `promoteKeyMemory` |
| CAS / expected_version | `npc_states.version` 与 `npc_memory_records.version` 单调递增；修订携带 expectedVersion，不匹配返回 VERSION_CONFLICT | `applyTrust` / `amendMemory` |
| Amendment 操作（CORRECT/INVALIDATE/FORGET 等） | 落地三种：CORRECT（改内容，版本+1）、INVALIDATE（置 SUPERSEDED，退出活跃视图）、FORGET（硬删除，被遗忘权） | `amendMemory` |
| SDK DLP 敏感值过滤 | 入库前过滤手机号、18 位证件号与 15 位以上长数字串 | `sanitizeForStore` |
| 学习只产 Candidate / 降级显式 | AI 不可用或门禁拦截时显式降级规则版，`fallbackReason` 记录原因（AI_NOT_CONFIGURED / GATE_BLOCKED 等），不静默吞掉 | `npcChat` |

## 未吸收（明确不做）

- PostgreSQL / Qdrant / 向量投影：本仓库约束为 SQLite + 无新依赖，检索场景（7 轮窗口 + 少量关键记忆）用不到向量。
- Memory Transaction v2 的 17 类操作与 Outbox：单写者 SQLite 场景下过度设计，保留 CAS 与幂等即可。
- Capability Token / Actor Grant：本产品学生免注册，沿用匿名 actor_id。

## 与规则层的关系

- 卡面唯一事实源不变：`docs/npc/` 卡片 → `data/npc_personas.json`（消费视图）→ 引擎 `assets/js/npc-engine.js`。
- 持久化层只存运行态（信任值、对话轮次、关键记忆），不存任何账本数字；数字门禁在出话前由 `preSpeakCheck` 把关（README 使用规则第 6 条）。
