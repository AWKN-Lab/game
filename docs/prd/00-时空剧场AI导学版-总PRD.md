# 〇、V2.1 修订（2026-11-28）：设计铁律与历史耦合修复

## 0.1 设计铁律（最高优先级，覆盖后续一切取舍）

**好玩的前提是学习到了历史，而不只是增加一个玩法。**

历史知识应该帮助孩子解决问题，而非成为阻挡孩子继续游戏的障碍。允许孩子判断错误、承担后果、重新调查、修正认知；通关允许失败与纠错，掌握认证独立评估。

**验收判据（V2.1 修订，采纳独立复核 M1）**：不采用"删史料仍通关即不合格"的单一刚性判据（可被强制点击伪耦合绕过）。每个历史学习单元以三条反事实对照验收：①保留信息删证物形式；②保留操作删历史信息；③改变史实关键变量保持操作。以决策质量与独立理解评估差异为准，排除点击与属性奖励造成的伪耦合。已有知识充分的孩子可直接判断并给出证据，无需重复读卡。

## 0.2 已证实的核心缺陷（经源码核验；判定与处置按独立复核分拆）

| 编号 | 缺陷 | 证据位置 | 复核判定 |
|---|---|---|---|
| F1 | 13 道证物调查题正确项全部位于第三位（39 个选项对象的 correctIndex 均为 2），无需阅读史料即可全对 | 五剧本 `type:"evidence"` 块；`engine.js:2027–2058` | 成立（P0） |
| F2 | 证物答错不阻断剧情，答对仅给属性收益；打开证据事件不代表阅读 | `engine.js:2083–2093` | 部分成立：错答继续属合理的失败可恢复设计，不得改为卡死；补可选提示与比较任务（P0） |
| F3 | 结局判定只依据收集品数量与属性阈值，无历史理解谓词 | `engine.js:1118–1138` | 部分成立：不改引擎判定；理解测量归 C 实验独立评估（P1） |
| F4 | 史料硬伤：工业革命剧本称 1833 年《工厂法》为"世界上第一部限制工时的法律"，实为 1802 年立法在先 | `industrial_revolution.html:1107–1108` | 成立（P0） |

## 0.3 方向修订：内容生产的基本单位从"剧本"改为"值得解决的历史问题"

- **C 实验（当前唯一新增内容投入）**：在工业革命剧本第三至五幕选取 10–15 分钟单元，围绕"仅有法律条文能否确认工厂实际合规"，复用汤姆、证物调查、信任与回响机制，基于英国国家档案馆 1833 工厂法教学档案设计史料探究任务。原型交付物与验证方案见 ENG-12。
- **传单短章（法国大革命）**：作为同一"历史问题"单位的第二实例排队，核心史料为 1789 年面包价格（8→14 苏）与"饥荒阴谋"谣言（largely imagined，恰为教学核心）。
- **A/B 路线之争暂缓**：A（原创新世界）与 B（现有五剧本续命）的排他性立项决策，服从 C 实验证据链后再定。

## 0.4 北极星指标（V2.1 修订，采纳独立复核 M8：三个独立指标，不作单一与条件）

1. **自主参与率**：分母为有平等自愿使用机会的孩子（排除无设备、学校禁用、家长限时），测无催促、无额外激励的自愿回访与续玩；
2. **学习增益**：所有分配者的前测、即时后测与 7 日延迟迁移（不以重复题目或背诵提示冒充增益）；
3. **联合达标率**（辅助）：有机会者中学习与乐趣同时达标的比例。

分母、有效机会、时间窗、基线、失访与无数据规则在实验预注册中确定。游戏时长、课堂完成率、测验分数为过程指标；禁止以诱导使用时长优化指标。家长指标（主动支持再次使用、时间与安全接受度）与教师指标（课程目标达成、备课时间、课堂可执行性、再次使用意愿）独立记录。

## 0.5 执行批次与暂缓清单（V2.1 修订，采纳独立复核 S0–S5）

| 批次 | 内容 |
|---|---|
| S0 | 文档与指标修正（母文档及依赖契约同步） |
| S1 | F1 随机化、F4 史实纠错、版本与埋点契约、明显资产故障 |
| S2（并行） | C 的史料核查、教师任务审查、纸面原型 |

**暂缓**（避免扩大改造面）：积分等级扩张（缺儿童价值证据，会混杂实验）、信任双轨全面迁移（弱网/离线/存档风险，先做显式映射与诊断）、死资产删除（须权属登记与浏览器实际引用复核）、远期世界营造。信任双轨不与 C 实验捆绑；C 纸面原型不依赖迁移。

**部署前置**：服务器公钥、端口放行（仅最小权限，不作全开放默认）、模型密钥。本地修复与纸面原型不依赖这三项。

# 一、结论先行

**V2.0 核心修订：产品的核心体验是"选择被记住"，而不是"AI 互动"本身。**

诊断结论（详见《时空剧场诊断报告与重设计蓝图》）：现有 4 个剧本共 115 个选择项全部不改变剧情走向，数值只在结局判定读取一次——问题在机制层，不在美术与呈现层。因此 V2.0 的产品主张是：

1. **后果密度优先于分支宽度**：保持单线时间轴，让选择改变 NPC 命运、资源状态和后续台词回响；选错走"失败可玩"（付出代价、剧情继续），不追求多分支。课标要求的史实覆盖完整保留。
2. **人物信任可见化**：摆上台面的不是数值条，而是 NPC 对玩家的态度变化（信任你的人会透露消息、求你办事、在结局为你作证）；数值退到幕后只做结算。
3. **AI NPC 互动是表达层手段**：AI 负责生成回响台词、驱动可对话 NPC、担任历史审稿人；事实层必须锚定剧本知识库，AI 不生成史实。AI 的角色是对手、证人、审稿人，不是老师——它逼学生思考，不替学生思考。
4. **双皮呈现**：同一引擎、同一剧情数据，两套皮——课堂皮（绘本/课件模式，投影友好、无游戏元素、可导出学情）+ 课后皮（现有游戏模式）。制度摩擦在课堂皮解决，吸引力在课后皮保留。

本次升级保留五个现有剧本、互动剧情引擎、卡牌、知识测试和学习记录。

产品保留三条既有闭环：

1. **教师导学闭环**：老师输入课堂条件，AI 从现有剧本和知识点中整理课堂目标、建议剧情、暂停提问、板书和课后任务。
2. **学生复盘闭环**：系统读取学生的真实进度、错题和评级，AI 输出掌握内容、混淆点、错因和复习动作。
3. **用户反馈闭环**：系统记录经过定义的产品互动，用户可以提交反馈和愿望，管理员据此处理问题并安排后续剧本与功能。

V2.0 新增演进路线（先一人，后多人）：

- **第一步（单人+AI）**：AI 对话 NPC、生成回响、历史审稿。用自由输入次数、对话轮数、回响被提及率验收。
- **第二步（+人）**：教师端导演模式、学生角色卡（信息不对称）、AI 主持人。验收课堂完成率与讨论参与度。
- **第三步（+IP）**：IP 角色卡与联名场景，以前两步跑通的数据为谈判基础。

学生和教师继续免注册使用核心能力。

管理员需要安全登录，才能查看匿名互动数据、用户选择、反馈和许愿池。

原"本期不建设全班共演、班级管理和实时投票"的边界自 V2.0 起调整：全班共演（课堂多人模式）进入 P1 规划，班级管理与实时投票仍为 P2。

# 二、产品目标

## 2.1 用户目标

### 教师

在两分钟内得到一张可以直接使用的导学卡，减少重新整理长教案的时间。

### 学生

在完成剧本后得到一张具体复盘卡，知道自己错在哪里、下一步做什么。

### 普通用户

遇到问题时可以在当前上下文直接反馈，也可以告诉产品团队最想优先开发的剧本和功能。

### 管理员

能够：

- 查看定义范围内的用户互动；
- 查看用户在剧本中的选择、答题和完成路径；
- 查看并处理用户反馈；
- 审核、合并和排期许愿池需求；
- 维护剧本元数据、知识点、AI 提示词和本地降级规则；
- 查看管理员操作审计。

## 2.2 业务目标

- 展示现有五部互动历史剧本的内容资产；
- 展示真实 AI 调用；
- 完成课前到课后的最小学习闭环；
- 建立用户需求进入产品路线图的反馈闭环；
- 用真实互动数据替代主观猜测；
- 证明普通电脑或手机可以使用；
- 控制课堂侧复杂度，确保比赛前完成。

## 2.3 成功指标

| 指标 | MVP 验收值 |
|---|---|
| 导学卡生成成功率 | ≥ 95%，含规则降级 |
| 导学卡生成时间 | 正常网络下 ≤ 20 秒 |
| 导学卡长度 | 一屏到一页 |
| 复盘卡使用真实数据 | 100% |
| 五个现有剧本回归 | 核心流程全部可运行 |
| AI 失败可用性 | 自动返回规则版 |
| 学生使用门槛 | 无需注册 |
| 核心事件采集成功率 | ≥ 98%，允许离线队列重试 |
| 用户选择可追踪率 | 关键选择节点 100% |
| 反馈上下文完整率 | ≥ 95% 自动带剧本、页面或节点 |
| 许愿处理率 | 管理员可完成审核、合并、回复和状态更新 |
| 管理后台访问控制 | 未授权用户 100% 无法访问 |

# 五、核心用户流程

## 5.1 教师流程

```text
进入剧本详情
→ 点击生成 AI 导学卡
→ 选择课堂时长
→ 选择学生基础
→ 输入教学重点
→ 选择投屏或学生自学
→ 生成导学卡
→ 使用剧本教学
```

异常流程：

```text
AI 超时或失败
→ 自动使用本地规则
→ 正常展示导学卡
→ 标记“规则版”
```

## 5.2 学生流程

```text
游客进入
→ 选择剧本
→ 完成剧情互动
→ 完成知识测试
→ 点击生成学习复盘
→ 查看掌握、混淆、错因和下一步
```

无有效学习数据时：

```text
点击复盘
→ 提示先完成知识测试
→ 提供返回剧本按钮
```

## 5.3 用户反馈流程

```text
在当前页面点击反馈
→ 选择反馈类型
→ 填写问题
→ 系统自动附带剧本、幕次、节点和页面
→ 提交
→ 用户获得反馈编号
→ 管理员处理并更新状态
```

## 5.4 许愿池流程

```text
进入许愿池
→ 选择剧本愿望 / 功能愿望 / 问题愿望
→ 填写标题和原因
→ 选择是否同意公开
→ 提交
→ 管理员审核
→ 合并重复愿望
→ 公开状态
→ 调研 / 计划 / 开发 / 已实现
```

## 5.5 管理员流程

```text
安全登录
→ 查看总览
→ 筛选日期、剧本、事件或匿名用户
→ 查看用户完整互动时间线
→ 查看选择、答题、反馈和愿望
→ 处理反馈
→ 审核和合并愿望
→ 设置产品回复、优先级、负责人和计划版本
→ 发布状态更新
```

管理员还可以继续：

# 七、数据原则

1. 学生和教师默认使用匿名 ID；
2. 本机 `localStorage` 继续负责学习续玩；
3. 云端事件系统只接收事件目录中的白名单字段；
4. 不宣称学生学习数据云同步；
5. 管理员是本期唯一需要正式服务端登录的角色；
6. 不上传密码、密码哈希和浏览器完整存储；
7. 自由文本只在用户主动提交反馈、愿望或 AI 输入时保存；
8. AI 请求只发送完成导学或复盘所需字段；
9. 所有 AI 输出保留来源字段和生成模式：`ai`、`rule` 或 `failed`；
10. 历史事实必须来自剧本内容系统；
11. 事件采集失败不得阻断剧情；
12. 管理员查看、修改和导出数据必须写入审计日志；
13. 不建立广告画像和未成年人商业画像；
14. 用户可以关闭数据改进计划并清除本机数据。

# 十一、非功能要求

## 稳定

- AI 超时不阻断页面；
- 五个原剧本不依赖 AI 才能运行；
- 新功能异常不污染原有学习数据；
- 事件上报失败进入本机队列；
- 事件重试必须幂等。

## 性能

- 表单提交后立即显示加载状态；
- AI 请求超时建议 15 秒；
- 超时后直接转规则版；
- 事件批量上报，不在每次点击阻塞页面；
- 管理员常用列表首屏建议 3 秒内完成。

## 内容

- AI 输出一页以内；
- 使用具体知识点；
- 不使用空泛鼓励；
- 不给学生贴标签；
- 不新增未核验史实；
- 用户提交文本公开前必须审核。

## 安全

- 管理员服务端登录；
- 管理接口权限校验；
- 密码不存前端；
- 登录和敏感操作限流；
- 管理员操作审计；
- 自由文本防注入和转义；
- 导出操作二次确认。

## 隐私

- 默认匿名；
- 最小字段采集；
- 用户知情；
- 支持关闭数据改进计划；
- 不采集屏幕录像和键盘输入；
- 不建立商业广告画像。

## 兼容

- 桌面浏览器；
- 手机浏览器；
- 普通投影环境；
- AI 不可用时的本地模式；
- 事件服务不可用时的离线队列。

# 十三、总验收

1. 老师可以从任一剧本详情页生成导学卡；
2. 导学卡包含目标、剧情、提问、板书和任务；
3. 学生完成测试后可以生成复盘卡；
4. 复盘卡使用真实错题和评级；
5. AI 失败时两类卡片仍可生成；
6. 五个原有剧本核心流程正常；
7. 页面删除不存在的云同步表述；
8. 第三方角色 IP 已完成替换或隔离；
9. 全新环境可以按 README 构建运行；
10. 管理员可以查看定义范围内的用户互动、选择和反馈；
11. 管理员可以按匿名用户查看完整事件时间线；
12. 用户可以提交希望优先开发的剧本和功能；
13. 管理员可以审核、合并、回复、排期和更新愿望状态；
14. 未授权用户无法访问管理员页面和接口；
15. 事件采集失败不影响剧情和学习；
16. 系统不采集密码、屏幕录像和无关私人信息。

# 十四、V2.0 验收指标（体验重设计）

| 指标 | 验收值 |
|---|---|
| 关键选择改变后续内容 | 每幕 ≥ 1 处可感知后果（NPC 命运 / 资源 / 回响台词） |
| 回响被提及率 | 第三幕回响台词与玩家第一幕选择相关率 100%（规则版同样达标） |
| 自由输入参与率 | ≥ 30% 玩家在 AI 对话中至少发起 1 次自由输入 |
| 对话轮数 | 中位数 ≥ 3 轮 |
| AI 事实违规率 | AI 输出与剧本知识库冲突率 = 0（审稿人拦截后为 0） |
| AI 失败可用性 | NPC 对话与回响自动降级规则版，剧情不中断 |
| 史实覆盖 | 单线结构下，课标要求史实 100% 出现在主时间轴 |
| 课堂皮可用性 | 投影环境可运行，无积分与游戏化元素 |

## V2.0 设计边界

- 不做全树分支：单线时间轴 + 后果密度 + 失败可玩；
- AI 不生成史实：事实层锚定剧本内容系统，AI 只做表达层；
- AI 不替学生思考：AI 角色限定为对手、证人、审稿人；
- 课堂皮不 gamify：无积分、无排行榜、无外部奖励（避免德西效应反噬内在动机）；
- 多人模式依赖第一步数据验证后再投入，不并行开发。
