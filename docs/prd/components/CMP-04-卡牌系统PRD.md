# CMP-04｜卡牌系统 PRD

> 状态：现有能力保持  
> 优先级：P1  
> 定义：卡牌系统是独立组件，不归属于账号或剧情页面

---

# 一、组件结论

卡牌系统管理卡牌数据、获取、图鉴、使用、练习和战斗。

卡牌可以被多个剧本复用，拥有独立配置、状态和交互，因此作为组件管理。

本次比赛不扩建卡牌玩法，只保证现有卡牌能够正常服务剧情学习。

---

# 二、组件边界

包含：

- 卡牌定义；
- 卡牌图鉴；
- 卡牌获取；
- 卡牌使用；
- 卡牌效果；
- 卡牌练习；
- 卡牌战斗。

不包含：

- 剧情正文；
- 账号；
- AI 导学；
- 学习报告。

---

# 三、模块 PRD

## MOD-CARD-01｜卡牌数据与图鉴模块

### 目标

统一卡牌信息和展示。

### 数据字段

```js
{
  id,
  name,
  knowledge,
  description,
  effect,
  color,
  applicableScripts
}
```

### 功能

- 展示已获取卡牌；
- 查看卡牌知识和效果；
- 未获取卡牌显示锁定；
- 按知识主题分类。

### 验收

- 卡牌信息来自统一配置；
- 图鉴不依赖某一个剧本页面；
- 卡牌知识可以关联知识点 ID。

---

## MOD-CARD-02｜卡牌获取与使用模块

### 目标

让卡牌在剧情中承担知识提示和选择辅助。

### 功能

- 剧情节点发放卡牌；
- 使用卡牌改变游戏数值或触发内容；
- 记录已使用卡牌；
- 结局条件读取卡牌状态。

### 本期要求

- 保持现有逻辑；
- 使用失败有提示；
- 不允许同一卡牌在同一限制节点重复使用；
- 卡牌状态可以保存。

### 验收

- 获取、打开图鉴、使用、结局读取形成闭环；
- 重开游戏后状态按产品规则重置。

---

## MOD-CARD-03｜卡牌练习与战斗模块

### 目标

通过独立练习巩固知识点。

### 功能

- 每日修行；
- 卡牌题目；
- 战斗回合；
- 正误反馈；
- 练习结果。

### 本期范围

只修复明显路径和数据错误，不增加新玩法。

### P2

- 根据学生错题推荐卡牌练习；
- 将复盘卡中的薄弱点跳转到相应卡牌训练。

---

# 四、依赖

- 从剧本内容系统读取知识点；
- 向互动剧情引擎提供卡牌效果；
- 向学习数据组件提供练习结果；
- P2 被 AI 复盘卡用于推荐练习。

---

# 五、不做

- 抽卡付费；
- 卡牌商城；
- 稀有度经济；
- 玩家交易；
- 大规模数值平衡改版。
