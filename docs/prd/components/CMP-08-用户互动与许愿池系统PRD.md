# CMP-08｜用户互动与许愿池系统 PRD

> 状态：已确认  
> 版本：V1.0  
> 优先级：P0 基础闭环，公开投票与复杂分析为 P1  
> 核心任务：让管理员看见用户怎样使用产品、在哪里卡住、希望下一步开发什么

---

# 一、组件结论

用户互动与许愿池系统负责采集产品内已定义的互动事件，汇总用户选择、学习行为、反馈与愿望，并给管理员提供查看、筛选、处理和排期依据。

该组件解决三个问题：

1. 用户实际怎样使用产品，不能只靠猜；
2. 用户在哪里放弃、选错、重复尝试，需要有证据；
3. 新剧本和新功能先做什么，应当让真实需求参与排序。

本组件不会记录用户屏幕，不会窃取键盘输入，也不会向管理员展示密码等敏感信息。

“所有互动”的产品定义是：

> 所有已经进入事件目录、对产品改进有明确用途、经过隐私审查的产品行为事件。

---

# 二、组件边界

## 2.1 包含

- 用户会话与核心互动事件；
- 剧本进入、进度、选择和完成事件；
- 知识点、答题和错题事件；
- AI 导学卡与学习复盘的调用结果；
- 用户主动提交的反馈；
- 用户主动提交的剧本愿望和功能愿望；
- 管理员互动看板；
- 用户行为时间线；
- 愿望审核、合并、排序和状态管理；
- 管理员操作审计。

## 2.2 不包含

- 学生真实姓名档案；
- 密码、验证码和支付信息；
- 屏幕录像；
- 键盘监听；
- 广告画像；
- 未经用户主动提交的私人聊天；
- 自动判断学生人格、家庭条件或心理状态；
- 学校班级排名。

| 角色 | 权限 |

# 五、模块 PRD

## MOD-INSIGHT-01｜用户互动事件模块

### 目标

将用户在产品中的关键行为记录为统一事件，使管理员能够回答：

- 用户从哪里进入；
- 看了哪个剧本；
- 走到哪一幕；
- 做了哪些选择；
- 哪些知识点反复出错；
- 是否完成测试和复盘；
- 哪一步发生退出或异常。

### P0 事件目录

#### 会话与页面

- `session_started`
- `page_viewed`
- `session_ended`

#### 剧本

- `script_viewed`
- `script_started`
- `act_reached`
- `script_resumed`
- `script_completed`
- `ending_unlocked`

#### 互动选择

- `choice_shown`
- `choice_selected`
- `pressure_choice_timeout`
- `evidence_opened`
- `card_selected`
- `collectible_obtained`

#### 学习

- `knowledge_point_viewed`
- `quiz_started`
- `quiz_answered`
- `quiz_completed`
- `learning_review_generated`

#### 教师导学

- `lesson_plan_requested`
- `lesson_plan_generated`
- `lesson_plan_failed`
- `lesson_plan_rule_fallback`

#### 反馈与许愿

- `feedback_submitted`
- `wish_submitted`
- `wish_voted`

### 统一事件结构

```json
{
  "eventId": "evt_xxx",
  "eventName": "choice_selected",
  "occurredAt": "2026-08-04T15:00:00+08:00",
  "anonymousUserId": "anon_xxx",
  "sessionId": "ses_xxx",
  "actorType": "student_guest",
  "scriptId": "american_revolution",
  "actId": "act_01",
  "nodeId": "choice_003",
  "payload": {
    "choiceIndex": 1,
    "choiceValueTag": "rule_of_law"
  },
  "appVersion": "1.0.0",
  "source": "web",
  "consentVersion": "privacy_2026_08"
}
```

### 采集原则

- 只采集事件目录中的事件；
- `payload` 使用白名单字段；
- 不上传密码、邮箱密码哈希或完整浏览器存储；
- 自由文本只在用户主动提交反馈、愿望或 AI 输入时保存；
- 事件发送失败不阻断剧情；
- 离线时进入本机队列，恢复网络后重试；
- 相同 `eventId` 必须幂等。

### 验收

- 每个核心互动可以在后台还原发生顺序；
- 用户选择包含剧本、幕次、节点和选项；
- 事件采集失败不影响原产品；
- 重试不会产生重复事件；
- 未在事件目录中的字段不会上传。

## MOD-INSIGHT-02｜管理员互动看板模块

### 目标

管理员可以看见全局使用情况，也可以进入匿名用户时间线查看一次完整体验。

### P0 首页指标

- 今日活跃匿名用户数；
- 今日会话数；
- 剧本开始次数；
- 剧本完成率；
- 各剧本平均停留时间；
- 选择节点参与率；
- 测试开始率和完成率；
- 平均正确率；
- 导学卡生成次数与成功率；
- 学习复盘生成次数与成功率；
- 新增反馈数；
- 新增愿望数。

### 筛选条件

- 日期范围；
- 用户类型；
- 匿名用户 ID；
- 会话 ID；
- 剧本；
- 幕次；
- 事件类型；
- 设备类型；
- AI 模式：`ai` / `rule` / `failed`；
- 反馈或愿望状态。

### 匿名用户详情

管理员可以查看：

- 首次访问时间；
- 最近访问时间；
- 会话列表；
- 体验过的剧本；
- 剧情完成情况；
- 所有选择记录；
- 证据、卡牌和知识点互动；
- 答题与错题摘要；
- AI 导学或复盘记录；
- 主动提交的反馈与愿望。

管理员不能查看：

- 密码；
- 浏览器完整存储；
- 未经采集授权的私人信息；
- 与产品改进无关的浏览记录。

### P1 分析

- 漏斗分析；
- 选择分布；
- 剧本流失节点；
- 错题热力图；
- 新旧版本对比；
- 用户回访分析；
- 反馈主题聚类。

### 验收

- 管理员能从一次会话看到完整事件时间线；
- 能查到某个选择节点的所有选项分布；
- 能定位剧本中退出最多的幕次；
- 能查看反馈与对应使用上下文；
- 普通用户无法访问管理员页面。

## MOD-INSIGHT-03｜用户反馈模块

### 目标

让用户在遇到问题、看不懂或体验不好时，可以在当前上下文直接反馈。

### 入口

- 全局“反馈”按钮；
- 剧本菜单；
- 选择结果页；
- 知识测试结果页；
- 教师导学卡结果页；
- 学习复盘卡结果页。

### 反馈类型

- 内容错误；
- 看不懂；
- 操作问题；
- 页面或资源故障；
- AI 回答问题；
- 学习建议；
- 其他。

### 提交字段

```json
{
  "feedbackId": "fb_xxx",
  "type": "content_error",
  "title": "这道题解析看不懂",
  "content": "希望再讲清楚根本原因和导火线的区别",
  "context": {
    "scriptId": "american_revolution",
    "actId": "act_01",
    "nodeId": "quiz_02",
    "page": "quiz_result"
  },
  "anonymousUserId": "anon_xxx",
  "allowContact": false,
  "status": "submitted"
}
```

### 管理状态

- `submitted` 已提交；
- `reviewing` 处理中；
- `need_more_info` 需要补充；
- `resolved` 已处理；
- `duplicate` 重复；
- `rejected` 不采纳。

### 验收

- 反馈自动带上当前剧本和节点；
- 用户不需要填写真实姓名；
- 管理员可以回复处理状态；
- 内容错误可以关联修复版本；
- 反馈不会公开展示未审核内容。

## MOD-INSIGHT-04｜许愿池模块

### 目标

让用户告诉产品团队：最想先开发哪个剧本、最希望增加什么功能。

### 愿望类型

1. **剧本愿望**
   - 想学习的历史事件；
   - 想体验的人物或时期；
   - 希望覆盖的教材章节。

2. **功能愿望**
   - 学习功能；
   - 剧情功能；
   - 卡牌功能；
   - 教师功能；
   - 复盘和报告功能；
   - 无障碍与轻量模式。

3. **问题愿望**
   - 希望子衿讲清的问题；
   - 希望洛书讨论的道法问题；
   - 希望新增的知识解释。

### 用户提交字段

- 愿望类型；
- 标题；
- 为什么想要；
- 希望解决什么问题；
- 可选教材年级和章节；
- 可选关联现有剧本；
- 是否同意公开展示；
- 匿名提交默认开启。

### 用户侧页面

```text
许愿池
├─ 我要许愿
├─ 热门剧本愿望
├─ 热门功能愿望
├─ 已进入计划
└─ 已经实现
```

### P0

- 提交愿望；
- 管理员审核；
- 用户查看审核通过的愿望；
- 显示愿望状态；
- 重复愿望由管理员合并；
- 用户可以对公开愿望点亮一次。

### 防滥用

- 提交频率限制；
- 文本长度限制；
- 敏感信息提醒；
- 垃圾内容过滤；
- 公开前人工审核；
- 匿名用户使用设备级去重投票。

### 验收

- 用户可以在一分钟内完成许愿；
- 能明确区分剧本愿望与功能愿望；
- 管理员能审核、合并和修改状态；
- 未审核内容不会进入公开列表；
- 同一匿名设备不能对同一愿望重复点亮。

## MOD-INSIGHT-05｜愿望治理与产品路线图模块

### 目标

将愿望从“留言”变成可处理的产品需求。

### 管理状态

- `pending_review` 待审核；
- `public` 已公开；
- `under_research` 调研中；
- `planned` 已列入计划；
- `developing` 开发中；
- `released` 已实现；
- `duplicate` 已合并；
- `rejected` 暂不采纳。

### 管理动作

- 审核公开；
- 编辑分类；
- 合并重复愿望；
- 关联已有 PRD；
- 关联 GitHub Issue；
- 设置负责人；
- 设置优先级；
- 填写产品回复；
- 标记计划版本；
- 发布上线说明。

### 优先级参考

```text
需求价值分 = 用户点亮数
           + 目标用户覆盖
           + 学习价值
           + 比赛/业务价值
           - 开发成本
           - 内容与合规风险
```

系统提供参考分，最终优先级由管理员和产品负责人确认。

### 路线图展示

用户可看到：

- 正在调研；
- 已进入计划；
- 正在开发；
- 最近实现。

不公开内部成本、人员信息和敏感商业信息。

### 验收

- 每个进入计划的愿望都能关联负责人和版本；
- 已实现愿望可以关联发布说明；
- 重复愿望的点亮数可以合并；
- 用户能看到愿望状态变化；
- 管理员处理行为写入审计日志。

# 八、隐私与未成年人保护

## 8.1 最小采集

- 默认使用匿名 ID；
- 不要求学生提交真实姓名；
- 不上传本机密码或密码哈希；
- 只收集事件目录明确列出的字段；
- 自由文本提交前提示不要填写手机号、住址、学校班级等个人信息。

## 8.2 用户知情

首次需要云端事件采集时展示简明说明：

> 我们会记录剧本进度、选择和答题结果，用于改进学习体验。不会记录密码，也不会用于广告画像。你可以在设置中关闭数据改进计划并清除本机数据。

## 8.3 管理权限

- 管理员按角色授权；
- 敏感操作写入审计日志；
- 普通管理员默认查看匿名数据；
- 自由文本和联系方式采用更严格权限；
- 导出数据需要二次确认。

## 8.4 数据保留

建议默认：

- 原始互动事件：180 天；
- 聚合统计：长期保留；
- 已解决反馈：365 天；
- 已公开愿望和产品回复：持续保留；
- 用户删除请求：按匿名 ID 删除可识别记录。

最终保留周期由正式隐私政策和部署地区要求确认。

# 十一、总验收

1. 管理员能够查看定义范围内的所有用户互动事件；
2. 能按匿名用户还原剧本进入、选择、答题、复盘和反馈时间线；
3. 能查看每个选择节点的选项分布；
4. 用户可以提交内容问题、体验问题和学习建议；
5. 用户可以许愿希望优先开发的剧本和功能；
6. 管理员可以审核、合并、回复、排期和更新愿望状态；
7. 学生和教师不注册也能使用核心产品；
8. 普通用户无法访问管理员数据；
9. 事件采集失败不影响剧情和学习；
10. 系统不采集密码、屏幕录像和无关私人信息。
